# 第一部分　一页纸总览（给非技术的读者）

## 这一版要做什么

卷知 1.2.1 已经能把试卷变成「知识点词典」、看板和分读者的 AI 报告。M9 要把它推到**公开测试（公测）**：让第一批陌生用户（培训机构的教研和老师、学校老师、家长）装上就能用，用得不顺时能说清楚哪里不顺。分三类事：

| 类别 | 一句话 | 谁最受益 |
|---|---|---|
| 一、让真实使用不再卡壳 | 修好同事和 Windows 用户实测遇到的 5 个问题，加运行日志和「导出诊断信息」，大批量导入提速 | 所有人，尤其是 Windows 用户 |
| 二、课程对照（新） | 上传自己的课程大纲（机构的课表、学校的教学进度、孩子在上的课），卷知告诉你：试卷里丢分的考点，对应哪一课；常考的考点，哪些课没覆盖；家长沟通怎么说 | 教研、老师、家长 |
| 三、老师版升级（新） | 老师版报告变成「错题集 + 错题知识点 + 做题方法 + 3 道同类变形题 + 学习进步建议」，带「口诀大招」和「答题卡」两种可以截图发给家长、学生的卡片 | 辅导老师、家长 |

另外，看板和报告的筛选栏加一个「试卷」多选下拉，可以直接勾选具体几份卷子来统计。

## 三条不能破的底线

1. **完全通用**。软件里不写任何机构、课程线的名字（同事的内部分支里写死了某公司的课程线，我们不能）。所有课程数据都是**用户自己上传**；示例和测试数据全部虚构；用单元测试扫描代码，出现禁用词就报错。
2. **数据留在本机**。课程大纲和试卷一样只存在用户电脑上。需要 AI 整理时，内容只发给用户自己配置的 AI 服务，上传前会明说。诊断信息默认不含密钥、不含学生信息。
3. **AI 的话不能直接发出去**。课程推荐、变形题、口诀都经过「事实核对」和老师的「我已核对」，推荐话术里不许出现价格、优惠、夸大承诺。课程匹配是 AI 建议，老师和教研随时可以改，改过的不会被 AI 覆盖。

## 分几步交付

| 版本 | 内容 | 大致工期 |
|---|---|---|
| 1.3.0-beta.1 | 修 5 个实测问题、运行日志和诊断导出、批量提速、试卷多选下拉、公测标识和反馈入口 | 约 3 周 |
| 1.3.0-beta.2 | 课程对照：上传大纲、AI 整理、核对修改、知识点对应到课、看板「课程对照」页 | 约 3 周 |
| 1.3.0-beta.3 | 报告带课程建议（老师版 / 完整版 / 家长版一句话）+ 老师版升级、口诀和答题卡、变形题 | 约 3 周 |
| 1.3.0 | 吸收公测反馈、Windows 真机验收、Word/WPS 打开检查 | 约 2 周 |

先修稳、再加新，是因为公测第一印象取决于「识别不完整」「上传慢」这类问题，而不是新功能。

## 需要你拍板的事（完整问题见最后一部分，这里先列要点）

1. 没有 GitHub 账号的老师，用哪个渠道反馈（微信群 / 表单 / 邮箱）？
2. Windows 缺中文识别包的用户，是否默认让图片和扫描件走 AI 读图（会把页面图发给 AI 服务商）？
3. 「错题集」：软件里没有学生真实成绩，只有 AI 估计的易错题，建议叫「易错题集」。同意吗？
4. 口诀卡用琥珀黄，但 DESIGN.md 规定琥珀是「语音」大类的专用色。要不要给导出卡片开一个明确的例外？
5. 课程大纲是否默认随「数据包」一起迁移？

# 第二部分　技术设计

## 0　阅读前提与总体约定

### 0.1　本文引用的现状（已核实）

- 架构：Electron 45 主进程（`src/main`）+ React 19 渲染进程（`src/renderer`）+ preload 白名单桥（`src/preload/index.ts`）。IPC 全部用 zod 校验，**每个新通道必须登记到 `src/main/ipc-channels.ts` 的 WRITE_CHANNELS 或 READONLY_CHANNELS，否则单测 `ipc-guard-audit` 失败**。
- 数据库：`node:sqlite`，迁移数组 `MIGRATIONS`（`src/main/db.ts`），当前 10 项（v1–v10）。升级前自动备份、失败回滚（`backupBeforeUpgrade` / `restoreBackup`）。单测 helper（`tests/unit/helpers/db.mjs`）**用正则从 db.ts 源码里把 `MIGRATIONS` 数组抠出来**在内存库上跑，所以新迁移必须写成数组的下一个元素，且只能依赖文件内已有的函数或自身代码。
- 设置：`settings(key, value_json)`；AI 配置存在 `settings.ai_config`，密钥单独加密存放（`ai_key_enc`，safeStorage）。
- AI 客户端：`src/main/ai/client.ts`，OpenAI 兼容、流式、对 429/5xx/超时指数退避重试（默认 3 次）、被长度截断时自动翻倍重试一次。`ai_usage` 表记每次调用的 token。
- 解析流水线：`pipeline/queue.ts`（提取，**单线程顺序**）→ `parse/queue.ts`（AI 解析，并发 = `concurrency`，界面上限 4）→ `parse/run.ts`（一份卷子内**逐批串行**，因为后一批要带前一批的上下文 `PREV_CONTEXT`）。
- 报告：`report/service.ts` 一次生成 = 一次 AI 调用（流式）→ `report/finish.ts` 收尾（去代码、核对引用、事实核对 `shared/factcheck.ts`、家长版净化）→ 存 `reports`；过期判断靠数据修订号 `data_rev`、提示词模板签名、数据指纹，**绝不自动重新生成**。
- 导出：Markdown / PDF（隐藏窗口 `printToPDF`，`shared/mdhtml.ts`）/ Word（`report/docx.ts`，jszip 手写 OOXML）。
- 设计系统：DESIGN.md「翻开的学习词典」。关键规则：玫红只表示易错；紫色只管词头、当前位置、每页唯一主按钮；六个大类色（含**琥珀 = 语音**）不能挪作他用；不新增 `warn` 琥珀；正文 ≥ 14px；颜色旁必须有字；空状态要教会界面；不放纯图标按钮。
- 没有任何依赖能读 xlsx（package.json 只有 jszip、mammoth、pdfjs-dist、yauzl、yazl、zod）。**不新增依赖**：用 jszip 自己读 / 写 xlsx（xlsx 本质是 zip + XML，约 200 行）。

### 0.2　通用性硬规则（课程相关一律适用）

1. 代码、提示词、种子数据、测试夹具、文档中**不出现任何真实机构或课程线名称**。新增单测 `no-hardcoded-course.test.mjs`：扫描 `src/`、`tests/`、`docs/`、`skills/`、`README*`，出现禁用词表里的词即失败（词表只放在单测里、由负责人维护，文档和代码注释里一律不写具体机构名）；再断言仓库里没有 `.xlsx` / `.csv` 课程文件（空白模板和示例在运行时由代码生成，不进仓库）。
2. 课程数据只能来自用户上传。没有上传时，所有课程功能显示空状态，不显示任何「默认课程」。
3. 示例 / 模板 / 夹具里的课程体系一律虚构，例如「示例体系 A」「基础级」「第 5 课 Animals」、教材对标写「示例教材 三上 Unit 2」。
4. 用词随场景调整，数据结构不变：培训机构（课程体系 / 级别 / 课次）、学校（教学进度 / 年级学期 / 周次或单元）、家长（孩子在上的课）。
5. 参考的真实大纲只在本机读过结构（多个 sheet = 多个级别；表头跨 2–3 行并含合并单元格；列有课次、主题、课程标题、字母和自拼、词汇、句型、实用表达、版本对标、能力目标、整季收获；「版本对标」可能出现不止一次；中间夹着「暑」「秋」这类赛季标记行）。**这些内容没有复制进本文或仓库**，只是用来确认「必须能处理任意列布局」。

### 0.3　迁移策略：v11 一次建好

M9 所有新表、新列放进**一个迁移 v11**（不改 v1–v10 任何一行）。理由：

- 数据包清单里记着 `schemaVersion`，每多一个版本号就多一套「新旧包互导」的组合要测；
- 公测用户不能降级（程序看到库版本高于自己会拒绝启动），迁移越少越安全；
- 空表不占空间，不影响现有功能。

配套纪律：

- v11 随 beta.1 发出就冻结。如果之后真的发现要改表，**只追加 v12**（只加列加表），不动 v11。
- 动手前先把本文第 7 节的表定义落成 TypeScript 类型 + 一个「v10 库升级到 v11」的单测，并加一个**冻结测试**：把 `MIGRATIONS[0..9]` 的源码哈希写死，谁改了旧迁移谁失败。
- 升级前备份、失败回滚沿用现有机制；公测说明里写明「每次升级会自动备份数据库」。

### 0.4　统一的 AI 内容守则（新功能全部遵守）

沿用现有产品原则：数字由程序算，AI 只解释；每个结论能回到原卷；样本少要老实说。具体到 M9：

- **程序拼装、AI 只写必须由 AI 写的那一小段**。课程对应关系、错题截图、知识点释义、表格全部由程序从数据库拼出来；AI 只写 150–200 字的话术、做题方法、口诀、变形题。这样 AI 输出变短（避开长度截断），也杜绝 AI 编造课程名。
- **引用令牌化**。课程用 `[课#12]` 这样的令牌交给 AI，输出后由程序替换成「示例体系 A · 基础级 · 第 5 课《标题》」；不在输入里的令牌删掉并告警（同 `stripUnknownCitations` 的做法）。
- **规则句只能来自证据**。凡讲英语规则的句子（口诀、变形题讲解、方法）都走 `checkRules` 对照证据，对不上标「未核实」，矛盾的在家长相关文字里直接删除。
- **所有 AI 产出带「AI 草稿」标识，老师「我已核对」后才能复制给家长或导出家长相关内容**（见附录 B 的门槛表）。
- **不做的事**：不自动重新生成（花钱）；不把 AI 匹配当作事实；不在任何推荐文字里出现价格、折扣、报名、保证、提分承诺。

## 1　功能 A：课程对照

### 1.1　用户故事

- 教研（机构）：「我把本季课程大纲 Excel 传进去，看板告诉我这批卷子里丢分的考点分别在哪一课讲，哪些常考点我们的课根本没讲，我好去补课程。」
- 学校老师：「我把本学期教学进度表传进去，看哪些常考点在进度里没安排，哪些安排得太晚。」
- 家长：「我把孩子在上的课程表传进去，看这次考试暴露的问题对应课程里的哪几课，回家让孩子复习哪几课。」
- 辅导老师：「出老师版报告时，自动附上『丢分点 → 建议复习哪几课』，还有一段能直接发给家长的话（不夸大、不提价格）。」

### 1.2　入口与信息架构

- **不新增侧栏项**（侧栏已有 6 项 + 设置，再加会挤）。
- 上传和管理放在侧栏的独立页面**「课程大纲」**（试卷库下面；课程大纲和试卷一样是知识库内容，不放进设置，也不藏进管理员设置：家长和学校老师也要自己传）。
- 看板新增第四个页签**「课程对照」**（现有：分布 / 同比 / 重难点）。
- 报告页生成面板：有已启用的课程大纲时，出现「加入课程对照」选项（见第 5 节）。
- 没有上传任何大纲时，看板「课程对照」页签显示**教学型空状态**：标题「这里会告诉你：丢分的考点在哪一课讲」，三步说明（上传课程表 → 核对 AI 整理结果 → 开始匹配），一个主按钮「去上传课程大纲」，一个次按钮「下载空白模板」，一行隐私说明。

### 1.3　上传向导（侧栏「课程大纲」→ 添加）

三步，顶部是步骤条，每步一个明确动作，随时可以回到上一步，关闭时有「放弃？」确认（沿用 `useDiscardGuard`）。

**第 1 步　选文件**

- 拖入或选择 `.xlsx` / `.csv`（`.xls` 提示「请用 Excel 另存为 .xlsx」；`.numbers` / `.wps` 同理）。也提供「粘贴表格」文本框（从 Excel 复制出来是制表符分隔），给不想找文件的人。
- 「下载空白模板」「下载示例（虚构数据）」两个次按钮：模板列固定为 课次 / 级别 / 主题 / 课程标题 / 字母与语音 / 词汇 / 句型 / 实用表达 / 教材对标 / 能力目标 / 备注，一个 sheet 一个级别，首行是列名，第二行灰字说明；文件由代码运行时生成（不进仓库）。
- **隐私说明（醒目）**：「课程内容会发送给你在『AI 服务』里设置的模型来帮忙整理；不会发给卷知开发者。不想发送：选『手动指定每一列』。」
- 填写：课程体系名称（默认取文件名）、使用场景（培训机构的课程 / 学校的教学进度 / 孩子在上的课）、学期或季度备注（可选）。场景只改措辞，不改数据结构。

**第 2 步　核对 AI 整理的结果（预览并修改，保存前什么都不落库）**

- 顶部一句话：「识别到 7 个级别、共 168 课。有 3 处需要你看一眼。」
- 左侧是级别列表（每个 sheet 一个级别，可改名、删除、合并两个级别、调整顺序）；右侧是该级别的课次表，可直接点单元格修改，可删行、加行。
- 表格上方有**列识别条**：把原表前 8 行显示出来，每列上方一个彩色小标签（课次 / 标题 / 主题 / 词汇 / 句型 / 教材对标 / 忽略…），标签是下拉，改了立即用本地规则重新套用到全表（**不再调用 AI**）。
- 警告列表（可点击定位到行）：缺课次编号的行已跳过、课次重复、某个级别一课都没识别出来、合并单元格已向下填充、某些列被自动忽略（见下方「价格列」）。
- **价格类列自动忽略**：表头含「价格 / 学费 / 费用 / 优惠 / 折扣 / 元」的列默认设为忽略，并提示「卷知不使用价格信息」。
- 底部：「保存课程体系」（主按钮）、「上一步」。保存后跳转到该体系的详情，并提示「下一步：让 AI 把知识点对应到课（约 N 分钟，预计用量约 M 万 token）」。

**第 3 步　保存**：成功后显示课程体系卡片。

**管理页**（侧栏「课程大纲」）：卡片列表，每张卡：名称、场景标签、级别数 / 课数、上传时间、「参与对照」开关（默认开）、匹配状态（未匹配 / 已匹配 / 大纲已更新需重新匹配）、操作「查看 / 重新上传（替换）/ 删除 / 重新匹配」。

- **替换**：用同名体系重新上传时问「替换『X』」还是「另存为新体系」。替换时按（级别名 + 课次）比对，显示「新增 3 课、修改 5 课、删除 2 课；已有的 40 条知识点对应中，6 条涉及改动的课，需要重新匹配」。人工确认过的对应（`locked`）只要课还在就保留。
- **删除**：二次确认；级联删除课、对应关系、推荐文字缓存；不影响试卷和报告（已生成的报告里的课程文字是当时的快照，报告标「已过期」）。
- **多个体系**：可以同时存在，看板和报告可选其中几个。

### 1.4　AI 整理表格：只让 AI 认列，不让 AI 抄内容

这是整个功能最重要的设计选择：**AI 不逐行改写课程内容**。

1. 本地读取：jszip 解析 xlsx（sharedStrings、workbook、sheet、合并单元格，向下 / 向右填充；日期按文本；隐藏 sheet 默认跳过并提示），CSV 自带解析（RFC 4180；先判 UTF-8 / BOM，失败按 GBK 解码——中文 Windows 的 Excel 另存 CSV 常是 GBK）。限制：每 sheet 最多 5000 行 × 60 列、最多 20 个 sheet，超出提示。
2. 每个 sheet 一次 AI 调用（提示词 `p5_course_cols`）：输入是 sheet 名 + 前 12 行 + 随机 3 行 + 最后 3 行（单元格截断到 60 字）。输出 JSON：表头占几行、级别名从哪来（sheet 名 / 某个单元格 / 手填）、各语义列对应哪一列（可多列合并，如两个「教材对标」）、要忽略的列、要跳过的行类型（赛季标记行、空行、整季收获行）、拿不准的地方列表。
3. 程序把这份映射**确定性地套到全表**。每课的内容字段直接复制单元格原文，不经过 AI 改写，所以不会有「AI 编出一节课」。
4. 校验：映射引用的列必须存在；识别出的课次数为 0 的 sheet 标红；课次非数字且无标题的行跳过并记警告。
5. AI 不可用或用户选择手动时：直接进第 2 步，列识别条全部为「未识别」，用户逐列选择。**没有 AI 也能用**，只是多点几下。
6. 兜底：表头极不规则、AI 映射后识别课数为 0 时，提示「可以用模板重新整理一份，或手动指定」。（PDF / Word 版大纲、纯文本大纲：本里程碑不做，列入后续；见 13 节。）

### 1.5　课程数据模型（v11）

```
course_outlines     课程体系
  id TEXT PK(uuid), name TEXT, scene TEXT('org'|'school'|'family'|'other'), term_note TEXT,
  source_name TEXT, source_hash TEXT, status TEXT('active'|'draft'),   -- draft = 命令行导入、尚未在窗口确认
  active INTEGER DEFAULT 1,            -- 参与对照
  rev INTEGER DEFAULT 1,               -- 课程内容每改一次 +1，用来判断匹配是否过期
  mapping_json TEXT, warnings_json TEXT, ai_model TEXT, created_at, updated_at
course_levels       级别（一个 sheet 一个）
  id INTEGER PK, outline_id → course_outlines ON DELETE CASCADE, name TEXT, sort INTEGER, grade_hint TEXT
course_lessons      课次
  id INTEGER PK, outline_id → CASCADE, level_id → CASCADE, seq INTEGER, no_label TEXT,
  title TEXT, theme TEXT, textbook_ref TEXT,                 -- 教材对标原文
  points_json TEXT,                                          -- [{kind:'word'|'pattern'|'phonics'|'expression'|'skill'|'other', label, text}]
  raw_json TEXT,                                             -- 原行单元格，保真，预览 / 追溯用
  search_text TEXT,                                          -- 拼好的检索文本（匹配和检索用）

  model TEXT, prompt_version TEXT, created_at,  PRIMARY KEY (outline_id, kp_code)
course_kp_map       知识点 → 课次（可多条）
  outline_id, kp_code, lesson_id → course_lessons ON DELETE CASCADE,
```

索引：`course_lessons(outline_id, level_id, seq)`、`course_kp_map(outline_id, kp_code)`、`course_kp_check(outline_id)`。

要点：

- `kp_sig` = 知识点名称 + 白话释义 + 例词的哈希。知识点库被编辑（改名 / 合并）后，对应缓存自然失效。
- `quote` 是防编造的关键（见 1.6）。
- 为什么不复用 `ai_analyses`：它的读取代码按 `kind` 默认 `p2_yoy` 使用，混进新类型有回归风险，单独一张小表更稳。

### 1.6　知识点 → 课次的 AI 匹配

**匹配对象**：库里至少有一道题标注过的知识点（非示例数据），包括二、三级。以后新增了知识点，看板提示「还有 N 个新知识点没匹配 [补匹配]」，不会自动调用 AI。

**调用方式**（提示词 `p5_course_match`）：

- 把整个课程体系压成紧凑行放在提示词前部（`#12 | 基础级 | 第5课 | 标题 | 主题 | 词汇… | 句型… | 对标…`），再附一批知识点（每次一个一级大类，约 30 个，含名称、白话释义、例词）。前缀相同，服务商的前缀缓存会生效，后续批次便宜。
- 输出每个知识点最多 5 条对应：`{kp, lesson:'#12', confidence:'high|medium|low', quote:'课次文本里的原文片段', reason:'≤30 字'}`，或 `{kp, none:true}`。

**程序侧校验（防幻觉）**：

1. `lesson` 必须是输入里出现过的 id，否则丢弃；
2. `quote` 必须逐字出现在该课次的文本里（忽略空白和大小写）；找不到就把 `confidence` 降为 `low` 并标「仅凭主题推测」；
3. 只有 `high` / `medium` 参与看板的主要统计和报告推荐；`low` 折叠在「可能相关（待确认）」里，不进报告；
4. 人工 `locked` 的条目不被覆盖；被否决的 (知识点, 课次) 不会再被 AI 加回来。

**成本提示**：保存体系后先显示预计规模（课数、知识点数、批次数、历史平均用量），用户点「开始匹配」才调用。匹配过程在设置页和看板空态里显示进度（第几批 / 共几批），可取消，已完成的批次的结果保留（逐批落库）。

**重新匹配**：大纲替换后只给「需要重新匹配」的标记，用户手动触发；锁定项保留；第一版是整体重跑（有前缀缓存，成本可控），增量匹配列入后续。

**人工修正**（看板里随处可做，也可在设置 → 体系详情 → 「知识点对应」里集中改）：

- 每条对应有「对 / 不对」两个按钮（文字按钮）；「不对」= 否决并锁定；
- 「添加课次」：搜索课次（按标题 / 词汇 / 句型）选一个，记为 `manual`、`confirmed`、`locked`；
- 「这个知识点其实没有对应的课」：写 `course_kp_check.result='user_none'`；
- 每次修改立即影响看板的数字，不需要重新调用 AI。

### 1.7　看板「课程对照」页签

页面顶部沿用书眉范围句（含「选中的 N 份试卷」等），下面：

- 一句大字结论（不用一排数字卡）：「这批试卷里最容易丢分的 12 个考点，9 个在『示例体系 A』里能找到对应的课，3 个没有课讲到。」（数字全部程序算。）
- 课程体系选择：已启用体系的胶囊多选；右侧「管理课程大纲」。
- 若某体系的匹配状态是「未匹配 / 已过期」：黄色提示框（用法框）+ 主按钮「开始匹配」；匹配前下面四块显示灰态说明，不显示空数据。

**块 1　丢分考点 → 对应课程**

- 行 = 丢分考点：取当前范围内「AI 估计易错题数 > 0」的考点按易错题数排序，加上「重难点」综合得分最高的主要考点（二级，各取前 N，合并去重，行内标明来源：「易错」「主要考点」）。复用 `stats.hot`，不重新算数。
- 每行：词头（考点名，紫色）+「易错」标签 + 白话一句 + 出现份数 / 总份数；右侧是课程胶囊：`示例体系 A · 基础级 · 第 5 课 《标题》`，最多显示 3 个，其余「+2 课」展开；`medium` 的胶囊虚线描边并带「可能」字样（状态靠文字和描边，不靠颜色）。
- 点胶囊打开右侧抽屉：课次详情（主题、词汇、句型、教材对标）、AI 的理由和原文片段、把握程度、「对 / 不对」。抽屉底部是该考点的原卷截图（沿用「出自原卷」）。
- 没找到课的考点：显示「没有找到对应的课」+ 按钮「我知道是哪一课」（→ 添加课次）。

**块 2　课程体系 × 级别 交叉**

- 行 = 课程体系，列 = 级别，格子（沿用热力格组件）里写：涉及的丢分考点数，下面小字「占本范围分值约 X%」（该级别能覆盖的丢分考点所占的分值占比，程序算，只算 `high/medium`）。
- 点格子 → 列出这个级别覆盖了哪些丢分考点、各在第几课。
- 说明一句话：「这是『哪些课涉及这些考点』，不是『学完就能提分』。」

**块 3　常考但课程没覆盖（给教研补课程用）**

- 条件：在当前范围内出现率高（默认前 30% 或至少出现在 2 份卷子里；样本太少时不下结论，显示样本提示）且在所有已启用体系里没有 `high/medium` 对应的考点。
- 每行：考点、出现份数、AI 估计易错题数、原卷截图缩略；按钮「其实有对应课」（纠正）。文案：「没有找到对应的课（AI 匹配的结果，请教研核对）」。
- 右上「导出 CSV」（与双向细目表导出同机制，带 BOM）。
- 学校场景措辞：「教学进度里没有安排的常考点」。

**块 4　家长沟通建议（AI 草稿）**

- 沿用 `AnalysisPanel` 的状态机：未生成（说明 + 生成按钮）→ 生成中（流式显示，取消按钮，显示已用时）→ 完成（结果卡片、缓存标记、「已过期，可重新生成」）→ 失败（白话原因 + 重试 + 保留未完成草稿，见 `ai_drafts`）。
- 输入：块 1 里选中的体系和丢分考点（取前 3–5 个，只含 `high/medium` 且有对应课的）。
- 结果卡片：150–200 字一段话；下方「复制」「重新生成」；卡片标题带「AI 草稿 · 请核对后再发给家长」。
- **复制门槛**：和家长版报告一致，点「我已核对」后才能复制（见附录 B）。

### 1.8　推荐话术的提示词与守则（`p5_course_advice`）

输入占位符：`SCENE`（培训机构 / 学校 / 家长）、`FILTER_DESC`、`SAMPLE_WARNING`、`LOST_POINTS`（考点白话名 + 白话释义 + 例句，来自证据表）、`COURSE_MATCH`（每个考点对应的课令牌 `[课#12]` 及其标题）、`EVIDENCE`。

系统提示要点：

- 只能使用输入里的考点和课令牌；不得编造课名、课时数、课程效果；
- 先讲孩子在家可以怎么练（给一个家长能判断对错的小例子），再说「如果想系统地练，可以看看 [课#12]」；
- 不写价格、折扣、优惠、报名、限时、名额；不写保证、一定、立刻、包过、提高 N 分、最好、第一、唯一；
- 不使用统计词和百分比；不说「孩子丢分了」（我们没有学生成绩，只有卷子上的易错点）；说「这类试卷里常见的易错点」；
- 150–200 字，口语，不超过 3 个考点；
- 规则句只能来自证据。

程序侧收尾（`src/main/course/advice-post.ts`，纯函数）：

1. 令牌替换为完整课名；未知令牌删除并告警；
2. **禁用词清理**：命中价格 / 营销 / 夸大词表的句子整句删除；含「数字 + 元 / 折 / %」的句子删除；删掉后不足 80 字则判失败；
3. 字数不在 150–200：告警「X 字，建议 150–200 字」，不自动裁剪；
4. `checkRules` 事实核对，标「未核实」；
5. 写入 `course_advice`，缓存键 = 范围 + 体系 rev + 匹配快照 + 提示词模板签名；数据变了标「已过期」，不自动重新生成。

### 1.9　报告里的课程内容

只在**有已启用课程大纲、且生成时勾选了「加入课程对照」**时出现；没有大纲时报告与 1.2.1 完全一致。所有 AI 写的部分过事实核对，并服从现有「我已核对」门槛。

| 版本 | 加什么 | 谁写的 |
|---|---|---|
| 老师版 | 新小节「课程对照与选课建议」：每个易错点下列「对应课程」（体系 · 级别 · 第几课《标题》，教材对标），小节末一段 150–200 字「可发给家长的话」 | 课程列表由程序拼；那段话由 AI 写（`p5_course_advice`），独立一次调用 |
| 完整版 | 末尾新表「课程对照」：知识点 \| 出现份数 \| AI 估计易错题数 \| 对应课程（最多 3）\| 把握（高 / 中） | 全部由程序拼，没有 AI |
| 家长版 | 可选：在「要不要担心」那一行之后，追加**一句**课程建议（≤ 40 字） | AI 写（`p5_course_hint`，独立调用），经家长版同一套净化 |
| 老板版 | 不加（老板版没有这个需求；若要，可在后续加「教研补课程清单」） | — |

实现要点：

- **分段生成**：报告从「一次调用」改为「主文 + 若干附加段」，每段独立调用、独立失败、独立重试（见 2.8 的 `report_parts`）。这样课程段出错不拖垮主文，也避免在一次调用里叠加内容导致输出过长被截断。
- **家长版字数门槛**：现有家长版要求复制到微信 ≤ 300 字且 3 条要点。追加一句后若超过 300，则丢弃这一句并写入告警「加上课程建议会超过 300 字，已省略」，而不是放宽门槛。
- **报告过期**：数据指纹加入 `course_outlines.rev` 和匹配快照，课程变了报告显示「已过期」。
- **「我已核对」**：老师版 / 完整版没有强制，但老师版「可发给家长的话」旁的「复制给家长」按钮**必须先对本报告点「我已核对」**；家长版沿用原规则（每句「未核实」要勾确认或删除）。
- 导出 Word / PDF / Markdown：课程小节与表格一并导出；未核对的老师版导出时，这一段前加「AI 草稿，未经核对，请勿直接发给家长」提示。

### 1.10　命令行影响（`docs/命令行.md`、`skills/juanzhi/SKILL.md` 同步）

- `course list`：列出体系（名称、级别数、课数、匹配状态）。
- `course import <文件> [--name] [--scene org|school|family] [--i-reviewed]`：导入并整理。**不带 `--i-reviewed` 时体系保存为 `draft`，不参与对照，必须在窗口里打开确认**（与 `papers confirm --i-reviewed` 同一精神）。

- `report generate --with-course <id>[,<id>]`：加入课程对照；没匹配过则报错并提示先 `course match`（退出码新增）。
- 不提供：删除体系、替老师点「我已核对」。

### 1.11　隐私

- 课程大纲只存本机 `db.sqlite`；诊断包**不含**任何课程内容（只含体系个数、课数这类计数）。
- AI 整理 / 匹配 / 话术会把课程文本发给用户配置的 AI 服务：上传向导第 1 步明说；设置里「AI 服务」页的隐私说明同步补一句。
- 数据包导出：课程大纲**默认随包迁移**（它是用户自己的业务数据，不是这台电脑的机器配置），导出对话框里有勾选项「不带课程大纲」。导入时合并规则：同 id 跳过；`course_*` 表按外键关系整体复制。需在 `pack/exporter.ts`、`pack/apply.ts`、`pack/stage-db.ts` 加入新表（待决策，见问题 5）。

### 1.13　工作量与风险

| 项 | 估计（开发会话·天，含单测） |
|---|---|
| xlsx / CSV 读写、模板生成 | 2 |
| 列识别提示词 + 映射套用 + 校验 | 2 |
| 上传向导三步 + 管理页 + 替换 / 删除 | 4 |
| 知识点匹配（批次、校验、缓存、锁定） | 4 |
| 看板「课程对照」页签（四块 + 抽屉 + 空状态） | 5 |
| 话术生成与后处理 | 2 |
| 报告集成（见 5、6 节中分段框架另算） | 3 |
| E2E 与 mock | 2 |
| 合计 | 约 24 天 |

主要风险：

1. AI 匹配质量参差，影响信任 → 只用 `high/medium` 做主要结论、原文片段可核对、人工可改并锁定、界面一律写「AI 匹配」。
2. 真实大纲布局千奇百怪 → 只让 AI 认列、程序全量套用、预览可改、手动模式兜底；需用 3–4 份不同布局的**虚构**夹具覆盖，并请一位持有真实大纲的同事在本机试跑（数据不入仓库）。
3. 大纲很大 → 压缩行 + 前缀缓存 + 分批 + 预估用量。
4. 学校场景「周次 / 单元」与「课次」概念不同 → 数据层统一用 `seq` + `no_label`，界面按场景换词，不另建模型。
5. 家长误把「匹配」当「保证」 → 所有文字里写「涉及」「可以复习」，禁用词表和提示词双重限制。

## 2　功能 B：老师版报告升级

### 2.1　用户故事

- 辅导老师：「出老师版报告时，一份文档里就有：这批卷子最容易错的题（原卷截图）、涉及的知识点讲什么、怎么教、3 道同类的变形题、给家长的学习建议。口诀和答题卡做成好看的图，我直接截图发家长群。」
- 家长：「收到的是一张清楚的『答题卡』，让孩子打印或对着写，不用看大段文字。」

### 2.2　新模块与「谁写的」

软件里**没有学生真实答题数据**，只有 AI 估计的易错题（`questions.error_prone`、`error_reason`）。所以不能叫「错题集」，建议叫**「易错题集」**并带「AI 估计」标识（待确认，见问题 3）。

| 模块 | 内容 | 来源 |
|---|---|---|
| 易错题集 | 每个易错点最多 2 道原卷题：截图（沿用引用 `[卷名 · 题号]` 与导出裁图）、题型、AI 估计的易错原因；已审核的题才显示参考答案 | 程序拼（数据库） |
| 易错知识点 | 考点白话名、释义、例句、例词、出现份数 | 程序拼（`kps` 的 plain / example / hint_words，审核过的易错说明） |
| 做题方法 | 每个易错点：怎么审题、怎么练、讲解时用哪句大白话（沿用现有「练法」「讲解要点」） | AI（规则句过事实核对） |
| 3 道同类变形题 | 见 2.5 | AI 出题 + 程序校验 + 第二次 AI 解答核对 |
| 学习进步建议 | 给家长和学生的 3–4 条具体建议（沿用现有「备课建议」的约束） | AI |
| 口诀大招（卡片） | 每个易错点 1 句顺口的记忆口诀 + 一个例子 | AI（规则句过事实核对，必须取自证据） |
| 答题卡（卡片） | 3 道变形题合成一张卡 | 程序拼（数据来自变形题表） |

程序拼的模块不经过 AI，所以事实风险最低；AI 只写方法、口诀、建议、变形题。

### 2.3　报告结构（老师版 v2）

1. 说明（沿用：AI 估计、样本提示）
2. 易错题集
3. 易错知识点
4. 做题方法（含口诀大招卡片）
5. 3 道同类变形题（含答题卡）
6. 学习进步建议
7. （有课程大纲时）课程对照与选课建议（见 1.9）

提示词 `p3_teacher` 升版（`PROMPT_DEFAULT_VERSION` 从 `v2.0` 升到 `v3.0`），只让主文 AI 写第 4、6 两节的文字；第 2、3 节由程序在收尾时插入；第 5 节由变形题流程产出。**用户自定义过 `p3_teacher` 提示词的，保持他的版本不变**（现有 `ai_prompts` 覆盖机制），并在提示词管理页标「默认版已更新，可对比」。

### 2.4　卡片：新的 Markdown 容器块

现有解析器（`shared/markdown.ts`）只支持标题、列表、引用、表格、代码、粗体、段落。新增**容器块**，所有渲染出口（界面、PDF、Word、复制到微信、Markdown 导出）用同一套语法：

```
::: trick 口诀大招
**一句话**：…
**例**：…
:::

::: answercard 答题卡 | 同类变形题
1. …题干… {choice: A, B, C, D}
2. …题干… {blank: 2}
3. …题干… {lines: 3}
:::
```

- 解析：`parseBlocks` 新增 `{type:'card', kind:'trick'|'answercard', title, lines}`；不认识的 kind 退化为普通引用块，旧版本读到不会崩。
- 渲染出口：
  - 界面 `MarkdownView`：React 组件 `TrickCard`、`AnswerCard`。
  - PDF `mdhtml.ts`：静态 HTML + 内联 CSS。
  - Word `docx.ts`：口诀卡 = 单格表格，底色淡琥珀、深琥珀边框、加粗标题；答题卡 = 表格：编号徽标（圆形用「形状」在 WPS 里不稳，退而用带底色的窄单元格）、虚线边框作答区（`w:tcBorders` 的 `dashed`）、选择题的 ○A ○B ○C ○D 用文字符号。**要在 Word 和 WPS 里各开一次验证**（README 已声明 Word 导出未逐一检查，这是已知缺口）。
  - 复制到微信 `markdownToWechat`：卡片转成「【口诀大招】…」「【答题卡】1. … ○A ○B」纯文本。
- 样式集中在一个文件 `shared/card-style.ts`（颜色、圆角、字号常量），界面 CSS 变量与 PDF / Word 的内联样式都由它派生，避免三处各写一份而走样。

### 2.5　三道同类变形题：AI 出题怎么做到可信

目标：老师拿到的题**可以直接给学生做**，错了不会误导孩子。

**出题**（提示词 `p4_variant_gen`，一次调用出 3 题）：

- 输入：排名前 3 的易错点，每个只给：考点白话名与释义、例词、证据里的例句、题型（**题干与选项原文不外发**：不把任何原卷题目发给 AI，原题只在本机用来查抄袭）。
- 只允许两种题型：**单选题（A–D）**和**填空题（单词给出或首字母给出）**——这两种能确定性地渲染成答题卡，并能被程序和第二次 AI 判分。
- 输出 JSON：`{kp, qtype, stem, options[], answer, explanation(≤40字), changed(相对原题改了什么)}`。
- 约束：考同一个知识点同一个坑；只有一个正确答案；换人名 / 物品 / 场景，不能照抄原题；词汇在小学范围内。

**程序侧校验**（`src/main/report/variants-check.ts`，纯函数）：

1. 结构：选择题必须 4 个选项且 `answer ∈ {A,B,C,D}`；填空题 `answer` 非空且出现在题干提示里；
2. **不抄原题**：与原题的字符 / 词集相似度（Jaccard）≥ 0.8 判为抄袭，丢弃；
3. **词汇范围**：用本机已审核试卷里出现过的英文词 + 知识点例词 + 一个小的功能词表做白名单，题干和选项里有白名单之外的词，标「含超出范围的词：x、y」（只提示，不阻断）；
4. 讲解里的规则句过 `checkRules`，对不上证据标「未核实」；
5. 选项去重、答案位置不全部相同。

**第二次 AI 独立解答**（提示词 `p4_variant_check`）：

- 只给题干和选项，**不给答案和讲解**，让模型自己做并说明一句理由。可选用另一个模型（设置里「核对用的模型」，默认同报告模型；用不同厂商的模型更独立）。
- 解答结果与出题答案**不一致** → 该题状态 `flagged`（答案有争议），默认**不进答题卡**，在报告里列在「已剔除的题」下，供老师查看并决定「仍然使用」；
- 一致 → 状态 `checked`。

**标识与门槛**：

- 每题带标签「AI 出题」，卡片页脚固定一行：「本题由 AI 根据原卷考点改编，已由程序和第二次 AI 解答核对；使用前请老师先做一遍」；
- 导出答题卡图片 / Word / PDF 前，老师需对**每道题**勾「我做过了」（或对整份报告点「我已核对」后统一放行；见问题 6 的选项）；未勾的题不进答题卡，导出按钮置灰并写明还差几题；
- **答案不印在答题卡上**：答案和讲解放在报告里答题卡下方的「参考答案与讲解（教师用）」。

### 2.6　卡片的视觉设计（遵守 DESIGN.md，并指出一个冲突）

- **口诀大招**：白纸底（原卷纸色，不随深色主题变），圆角 18px，1px 细线框；顶部一条淡琥珀色横幅，写「口诀大招」（14px 600，墨色字，不用琥珀做文字色）；口诀本身 22px 加粗大字，英文单词和例句用 Source Sans 3 斜体；下方一行小字「出自考点：xxx」。
- **答题卡**：白纸底；顶部「姓名 ______　日期 ______」留空（不含任何学生信息）；每题左侧一个**编号徽标**（实心圆，墨色底白字，不用紫色——紫色只给词头和主操作）；选择题 ○A ○B ○C ○D；填空 / 书写区用**虚线框**；底部「AI 出题」小标签。
- 三题放在同一张卡里，宽度固定 720px，导出图片 2 倍清晰度，方便一张截图发出去。
- **冲突**：DESIGN.md 规定琥珀（#B98733）是「语音」大类专用色，还写了「不要在新界面用 `warn` 琥珀」。口诀卡要求琥珀。方案：为导出卡片新增**独立的「卡片色」令牌**（`tokens.ts` 里 `card-amber` 系列，浅 / 深两套，文字对比度 ≥ 7:1），写进 DESIGN.md 并声明「仅用于导出卡片，不用于应用界面，不与大类色混用」。需负责人同意（问题 4）。如果不同意，备选是用陶土 / 紫色浅底，但「amber highlight」的辨识度会下降。

### 2.7　「复制成图片」

- 卡片旁有「保存图片」「复制图片」两个文字按钮。
- 实现：主进程用一个隐藏窗口加载与 PDF 同源的静态 HTML（强制浅色、固定宽度），`webContents.capturePage` 以 2 倍缩放截图 → 存文件（系统另存为）或写剪贴板（`nativeImage` → `clipboard.writeImage`）。不引入新依赖，也不受当前主题和滚动位置影响。
- 新通道 `report:cardImage`（保存图片会写用户选定的文件，复制只写剪贴板，归 READONLY）。

### 2.8　数据模型（v11）

```
report_parts        报告的分段（主文 + 附加段），支持单段重试
  report_id → reports ON DELETE CASCADE, part TEXT('main'|'course'|'tricks'|'variants'|'parent_hint'),
  status TEXT('ok'|'failed'|'skipped'), markdown TEXT, message TEXT, detail TEXT,
  model TEXT, prompt_version TEXT, usage_json TEXT, created_at,  PRIMARY KEY (report_id, part)
report_variants    变形题
  id TEXT PK, report_id → CASCADE, seq INTEGER, kp_code TEXT, source_question_id TEXT,
  qtype TEXT, stem TEXT, options_json TEXT, answer TEXT, explanation TEXT, changed TEXT,
  status TEXT('checked'|'flagged'|'dropped'), teacher_ok INTEGER DEFAULT 0,
  check_json TEXT,                    -- 程序校验结果 + 第二次解答结果
  model TEXT, check_model TEXT, created_at
reports（已有表加列）
  options_json TEXT                    -- 生成选项：{course:{outlineIds,...}, parentHint:bool, ...}，参与缓存键
```

不把变形题只存成 Markdown，是因为答题卡要结构化渲染、要逐题勾「我做过了」、要单独记录核对结果。最终的 `reports.markdown` 由程序把各段拼装而成，所有旧的出口（复制 / 导出 / 删句 / 过期判断）继续只认这一份 Markdown。

### 2.9　分段生成的流程

```
generateReport(filter, reader, options)
  1. main     ：现有流程，提示词按 reader 选择（teacher 用 v3.0）
  2. tricks   ：口诀（teacher）            ← 独立调用，失败不影响主文
  3. variants ：出题 → 程序校验 → 第二次解答（teacher）
  4. course   ：课程段（若勾选且有体系）
  5. parent_hint：家长版的一句话
  assemble()  ：把各段按顺序拼成最终 markdown，插入程序拼的易错题集 / 易错知识点
```

- 进度条显示「第 2/4 步：生成口诀…」，每步可单独失败；失败的段在报告里显示「这一部分没有生成，点『重试这一部分』」，重试只重跑该段并重新拼装；
- 全部成功才计入「历史最多 100 条」之类的现有计数规则没有变化；
- 取消 = 中止当前步骤，已完成的段保留为未完成草稿（沿用 `ai_drafts` 的做法）。

## 4　功能 D：实测问题的设计修复

### 4.0　先说根因：两处代码事实解释了 D1–D3 的大部分现象

1. **Windows OCR 不给置信度，固定写 0.8**（`native/windows/ocr.ps1` 第 126 行），而解析阶段只有在 OCR 置信度 < 0.55 时才改用视觉模型（`parse/run.ts` 的 `LOW_OCR_CONF`）。结果：Windows 上只要 OCR 返回了几行字（哪怕引擎是 en-US、中文全是乱码），就**永远不会**触发视觉模型。这就是「Windows 识别不完整」+「视觉模型好像没在工作」的同一个原因。提示只被记在 `papers.warning` 的一句话里（「OCR 使用 en-US 引擎，中文可能识别不全」），用户不一定看到。
2. **同一个 `model` 同时用于拆题和写报告**（`AiConfig.model`），默认值是推理模型 `deepseek-v4-pro`（`ai/types.ts`、`providers.ts` 里 `reasoning:true, defaultMaxTokens 32768`）。推理模型先思考再写，输出上限被思考占满，于是触发「写不完 → 自动翻倍重试 → 仍不行 → 对半拆批重试」（`client.ts` 的 `escalateOnLength`、`run.ts` 的 `halveBatch`），一份卷子要反复解析很多次。另外 `ai_config` 里只有**一个** `base_url` 和**一个**密钥，视觉模型与文本模型共用。

### 4.1　D1　「无法识别图片」：测试连接要分别测文本模型和视觉模型

**现状**：设置页已有「测试连接」（文本）和「测试视觉模型」两个按钮，但：用户常常只点第一个；HTTP 403 与 401 都被翻译成同一句「API Key 无效或没有权限」（`client.ts` 的 `statusError`），用户无法判断是密钥错了还是这个密钥没有开通这个模型；视觉测试用的是 128×128 纯色图，只能说明请求没被拒，不能说明模型会看图。

**设计**：

1. 一个按钮「测试全部」，依次测三项并以清单显示：
   - 拆题模型 ✓/✗（耗时）
   - 写报告模型 ✓/✗（与拆题模型相同则显示「与拆题模型相同，不重复测」）
   - 视觉模型 ✓/✗（没填则显示「未设置：照片 / 扫描件在 Windows 上可能识别不完整」，附「怎么设置」）
   各项也可单独重测。保存配置时若视觉模型是新填的，提示「还没测试，建议测一下」。
2. 错误码细分：`AiError` 新增 `forbidden`（HTTP 403），与 `auth`（401）分开：
   - 401：「密钥不对：请重新复制，注意前后不要有空格」；
   - **403：「这个密钥没有权限使用这个模型（模型：xxx）」**，下面分步说明「怎么办」：
     1. 到服务商控制台，给这个密钥开通该模型（有的服务商要先「开通模型」或创建「推理接入点」，模型名要填接入点 ID）；
     2. 或者换一个这个密钥有权限的模型；
     3. 或者让视觉模型使用另一个服务商 / 另一把密钥（展开「视觉模型用不同的服务」）；
     4. 点「查看详情」可以看到服务商返回的原话（已脱敏），方便找管理员或客服。
   - 404：「找不到这个模型：名字写错，或还没开通」；
   - 429：区分「太快」与「额度不足」（从响应体关键词判断，不确定就两种都说）。
3. 允许视觉模型使用独立的服务地址和密钥：`ai_config` 新增可选字段 `vision_base_url`（空 = 同上），密钥新增第二个加密槽 `ai_key_vision_enc`（空 = 同上）；界面放在「视觉模型」下的折叠项「视觉模型用不同的服务商 / 密钥」。`secret.ts` 保持「渲染端只能写入和清除、读不回」的约束。
4. 视觉测试改成真的看图：生成一张 64×64 的小图，上面用点阵画两个字符（如「7K」），请模型回答图上写了什么；回答包含这两个字符 = 「能看图」；模型有回应但答不对 = 黄色提示「能连通，但可能不会看图，请换一个带视觉能力的模型」。图由代码生成（沿用 `ai/png.ts`），不带任何外部素材。
5. 解析前预检：如果配置了视觉模型，且最近一次视觉测试失败或从未测过，解析队列开始前做一次 1 次调用的快速预检（结果缓存 10 分钟），失败则在处理队列页顶部显示「视觉模型现在用不了（原因）。本次将只用本机识别。[去设置] [仍然继续]」，而不是等到解析中途才失败。
6. 视觉批次真正失败时：`ParseError` 的白话消息改为「AI 读图失败：这个密钥没有权限使用视觉模型 xxx」，并在试卷详情里给「改用本机识别重试」按钮（仅当本机识别可用）。

**测试**：单测——`forbidden` 映射与消息文本；视觉测试图生成；预检缓存。E2E——mock 对指定模型返回 403（扩展 `mock.script`，按 `model` 过滤）→ 测试清单第三项失败且文案正确，前两项成功。**工作量**约 1.5 天。**风险**：不同服务商 403 的响应体格式不一，详情只做脱敏截断，不依赖解析。

### 4.2　D2　Windows 识别不完整：每份卷子明说用了什么识别、为什么

**设计**：

1. **识别方式记录**（v11，`pages` 新增列）：`recognizer`（`pdf-text` / `mac-vision` / `win-ocr` / `docx-text` / `vision-model`）、`ocr_lang`（如 `zh-Hans-CN` / `en-US`）、`ocr_ms`、`rec_reason`（为什么用它：`text-layer-ok` / `no-vision-model` / `vision-precheck-failed` / `vision-forbidden` / `low-quality` / `lang-mismatch` 等枚举，界面再翻成白话）。
2. **不再相信 Windows 的固定置信度**。新增本机质量判断 `ocrQuality(lines, lang)`（纯函数，沿用 `pipeline/textquality.ts` 的思路）：
   - 引擎语言不是 `zh*` 且页面本应含中文 → 直接判 `lang-mismatch`（无需看文字）；「本应含中文」的判断：同一份卷子里已有任何一页识别出的 CJK 字符占比 ≥ 阈值，或试卷标题 / 文件名含中文；否则不下结论；
   - 乱码比例（既非字母数字、也非中日韩、也非常见标点的字符占比）高；
   - 平均行长异常短、行数异常少；
   两者任一命中 → 该页质量记为低。
3. **解析选页策略**（`preparePages`）：质量低且已配置并可用视觉模型 → 该页走视觉模型；不可用 → 仍走文本，但**这份卷子标记「识别可能不完整」**。新增设置 `vision_policy`：
   - `auto`（默认）：识别不好的页才读图；
   - `images_always`：图片和扫描件一律读图（Windows 没装中文识别包的人可选；**会把页面图发给 AI 服务商**）；
   - `never`：从不读图。
   默认值与「是否要提示 Windows 用户改选 `images_always`」见问题 2。
4. **每份卷子可见的提示**：
   - 试卷库列表行：小标签「识别可能不完整」（文字，不只靠颜色）；
   - 处理队列行 / 试卷详情页 / 审核页顶部：一张「识别方式」小卡：
     「第 1–3 页：Windows 自带识别（English）　中文可能认不全　[怎么安装中文识别]」
     「第 4 页：AI 读图（模型 xxx）」「第 5 页：PDF 自带文字层」；Word：「Word 文件：直接读取文字，不经过识别」。
     每条后面一句「为什么」；
   - 报告的告警里加一行：「其中 N 份卷子的识别可能不完整，相关数据请谨慎使用」（`reports.warnings_json`，同样走样本提示机制）。
5. **Windows OCR 中英文安装教程**：
   - 新文档 `docs/Windows文字识别安装.md`（中文）与 `docs/Windows-OCR-Setup.md`（English），README、安装指南第四部分、应用内帮助页互相链接。现有安装指南第四部分已有中文步骤（设置 → 时间和语言 → 语言 → 添加中文（简体）→ 勾选「光学字符识别」→ 重启本软件），新文档补：Windows 10 与 11 的菜单差异（带截图位置说明）、**PowerShell 命令版**（管理员运行：`Get-WindowsCapability -Online | Where-Object Name -like 'Language.OCR*zh-CN*'`，再 `Add-WindowsCapability -Online -Name Language.OCR~~~zh-CN~0.0.1.0`；**命令名需在真机上验证后再写入文档**）、公司电脑被 IT 限制时的替代办法（改用视觉模型，或让 IT 安装）、装好后如何确认（设置 → 管理员设置 → 文字识别应显示 zh-Hans-CN）、常见失败（没联网、Windows 更新被禁、家庭版限制）。
   - 应用内「怎么安装」按钮（仅 Windows 且检测到引擎语言不是 zh 或没有引擎时出现），出现位置：导入试卷后的提示、识别方式小卡、设置里的 OCR 状态卡。点击打开一个对话框：三步文字说明 + 「打开 Windows 语言设置」按钮（主进程 `shell.openExternal('ms-settings:regionlanguage')`，**只允许这一个固定 URI**，不接受渲染端传入）+ 「复制 PowerShell 命令」+ 「重新检测」+ 「查看完整教程」。macOS 不显示（Vision 自带中文）。
   - 导入时的主动提示：Windows 上第一次导入图片 / 扫描件 / 照片前，如果 `ocr:status` 显示没有中文引擎，在导入结果里弹出提示条而不是静默继续：「这台电脑还没装中文识别，图片里的中文会认不全。[怎么安装] [改用 AI 读图] [继续]」。
6. **视觉模型设置引导**（AI 设置页顶部卡片「让 AI 能读图」）：为什么需要（扫描件 / 照片 / Windows 没装中文包）；怎么选（预设里标出支持图片的模型）；权限提醒（见 D1 的 403）；费用提醒（读图比读文字贵，默认只用在识别不好的页）；隐私提醒（页面图会发给服务商）；末尾「测试视觉模型」。

**测试**：单测——`ocrQuality` 决策表（en-US 引擎 + 中文页、zh 引擎正常页、空白页）、`preparePages` 在三种 `vision_policy` 下的选择、识别方式记录的写入；沿用 `tests/e2e/ocr-diagnose.ps1`（Windows 云端）核对 `-Check` 输出。E2E——用注入的假 OCR 结果（lang=en-US、conf=0.8）验证试卷出现「识别可能不完整」标签与识别方式小卡；mock 视觉模型可用时该页走视觉。**Windows 真机验收**加入 `docs/Windows验收清单.md`：卸载中文 OCR 能力后导入扫描件 → 看到提示 → 点按钮打开语言设置 → 装好 → 重新检测通过。**工作量**约 3 天（不含教程截图与真机验证）。**风险**：「本应含中文」的判断会误判纯英文卷（缓解：只在有 CJK 证据时才判；误判的后果只是多提示一句）；`ms-settings:` 在受管电脑上可能被屏蔽（缓解：同时给出 PowerShell 和教程）。

### 4.3　D3　Windows 上传慢、反复解析：拆题模型与写报告模型分开

**设计**：

1. **配置拆分**：`ai_config` 新增 `parse_model`（拆题用，空 = 同「写报告用的模型」`model`）。界面两栏：「拆题用的模型（推荐：快速、不带深度思考的）」和「写报告用的模型（可用更强的）」，各自显示一个小标签「快速」或「深度思考型（较慢）」（来自 `modelProfile(model).reasoning`）。视觉模型保持独立。迁移：旧配置没有 `parse_model` 字段，读取时默认空，行为与 1.2.1 完全一致；**不自动替用户换模型**。
2. **预设里加「推荐拆题模型」**：每个服务商预设新增 `parseModel`（非推理型）。能查证的就写，**查不到的不猜**：
   - 通义 `qwen-plus`、Kimi `kimi-k2-0905-preview` 在现有模型档案里已标 `reasoning:false`；
   - DeepSeek / 智谱 / 豆包的当前模型大多是推理型。很多厂商支持用请求参数关闭思考（各家参数名不同），**需要逐家查证文档并用真实密钥验证后再启用**；设计上留一个开关 `parse_thinking: 'default' | 'off'`，`off` 时按服务商加对应请求参数（`ModelProfile` 里记 `disableThinkingParam`）。这是 beta.1 的一个**研究任务**（0.5–1 天），结论写进 `providers.ts` 的注释。
3. **检测并建议**：
   - 写入记录：`parse_batches` 新表，每个批次一行（见 7 节）：模型、模式、页数、尝试次数、是否因长度被截断、是否加长重试过、思考 token、总 token、耗时、错误码；
   - 规则：同一个拆题模型最近 10 个批次里，有 ≥ 3 个发生「截断 / 加长重试」，或单批耗时中位数 > 90 秒 → 在处理队列页和设置页显示提示条：「你用的拆题模型 xxx 是深度思考型，拆一份卷子要反复重试，比较慢。建议在设置里把『拆题用的模型』换成更快的（如 yyy）。[去设置] [以后不再提示]」。**只提示，不自动切换**（问题 10）。
   - 第一次使用时（配置里的拆题模型是推理型）也在设置页保存时给出同样的预防性提示。
4. **诚实的进度**：
   - 队列行显示「第 2/4 批 · 已用 1 分 20 秒 · 重试 1 次（输出较长，已自动加长）」；
   - 估算时间用本机实测：取最近 10 个批次的中位耗时 × 剩余批次数，显示「按这台电脑最近的速度，预计还需约 N 分钟」；样本不足时写「还没有足够数据估算」，不再写固定的「通常 2–3 分钟」；
   - 某一批耗时超过中位数 2 倍时显示「这一批比平时慢，仍在等待服务商响应」，并给「取消」。
5. **重试可见**：试卷详情里「解析记录」折叠区列出每批的尝试次数和原因（不含正文），供排查。

**测试**：单测——推荐提示规则（边界：9 批不触发、10 批里 3 个触发、已选「以后不再提示」）；ETA 计算；`parse_batches` 写入。E2E——mock 推理模型 + 连续截断（现有 `{type:'length', times:2}`）→ 队列页出现建议条；换成非推理模型后不再出现。真实 AI 对比（`npm run test:real-ai`）：用两份样卷，对同一服务商的推理模型与快速模型各跑一遍，记录耗时、token、题数、知识点一致率，写进验收记录，**作为是否改默认值的依据**。**工作量**约 3 天（含研究 1 天）。**风险**：不同厂商关闭思考的参数不统一；换成快速模型后拆题质量可能下降，需要对比样卷后才能把它设为默认推荐。

### 4.4　D4　截图 / Word 分析不准：区分是识别错了还是 AI 拆错了

**先弄清各格式的识别路径**（均已读代码）：

| 输入 | 文字从哪来 | 用到 AI 视觉吗 |
|---|---|---|
| 文字型 PDF | PDF 自带文字层（`pdf-text`） | 否 |
| 扫描 PDF / 图片 / 截图 / 照片 | 本机 OCR（Mac Vision / Windows OCR）；OCR 失败、没字、或置信度 < 0.55（Windows 永不触发，见 4.0）才用视觉模型 | 视情况 |
| Word `.docx` | mammoth 直接读文字（**不经过 OCR**），图片落盘成 `[图n]` 占位 | 否（带图的 docx 文字少于 10 字时才提示需视觉模型，但 docx 页没有页面图，`preparePages` 里 docx 一律走文本） |

**Word 分析不准的几个疑点（待用真实文件验证，不当事实）**：

1. `htmlToText`（`pipeline/extract.ts`）把 `</li>` 变成换行并去掉所有标签，**Word 自动编号（1. 2. 3.）不是文字，会整个丢失**，AI 拿到的是没有题号的段落，只能猜题号；
2. 下划线（填空横线常用带下划线的空格表示）被丢弃，填空题的「空」消失；
3. 文本框里的文字被丢（代码已能检测并告警，但没有提取）；
4. 表格被拍平成制表符分隔的行，选项排成一行时选项边界不清；
5. 公式 / 图片题（`[图n]` 占位）AI 看不到图。

**设计**：

1. **docx 提取修正**（建立在上述疑点被样例验证之后）：
   - `<ol><li>` 转换时带上序号（沿用 mammoth 的列表结构数顺序；多级编号尽量保留层级）；
   - mammoth `styleMap` 打开下划线，转换为 `____`（下划线空白）或 `_词_`；
   - 用已经打开的 jszip 提取 `w:txbxContent` 里的文字，追加到相应位置并在警告里说明；
   - 表格输出成「单元格 | 单元格」的行；
   - 对每个 docx 记录「提取体检」：列表段落数、被补回编号数、下划线数、文本框数、图片数，写入诊断信息。
2. **「对照原文」抽屉（审核页每道题）**：三层并排——原卷截图（有则显示）→ 识别原文（该题范围内的 OCR / 文本层 / docx 文本行，按 `anchor_ref` / `bbox` 取）→ AI 拆出的题干与选项；用词级 diff 高亮差异。
3. **判定一句话**（程序启发式，写明是推测）：
   - AI 的题干在识别原文里**找不到**（模糊匹配 < 85%）→「AI 拆题改写或编造了内容」；
   - 识别原文本身**像乱码**（乱码比例、不在已知词表的怪词、数字混字母如 `l0ve`、该页判为低质量）→「识别原文就不对（识别环节的错误）」；
   - 两者一致但与截图不符 → 「识别和 AI 都一致，请对照截图判断」。
   Word 文件的提示固定为「Word 直接读取文字，不经过识别；如果这里不对，多半是文档里的编号 / 下划线 / 文本框没读到，或 AI 拆题错了」。
4. **页面级体检摘要**（试卷详情）：每页识别方式、行数、平均置信度（Windows 标「无置信度」）、乱码比例、CJK 占比；整份卷子「N 道题中 M 道在原文里找得到」。
5. 可选（beta.3 之后）：「让 AI 读图重试这一道题」，把该题的截图交给视觉模型读一遍，作为第三方参照，花一次调用。

**测试**：单测——docx 提取（用 jszip 现场生成含自动编号、下划线、文本框、表格的 docx 夹具，断言输出文本含编号 / 下划线 / 框内文字）、`verdict` 判定函数的表驱动用例。E2E——故意造一张 AI 结果与原文不符的题 → 抽屉显示「AI 改写」判定。**工作量**约 3 天。**风险**：Word 编号的各种变体很多（多级、自定义格式），只保证常见情形；判定是启发式，措辞必须是「可能」。

### 4.5　D5　「点击截取知识点」据报不再有效：代码路径调查与验证方法

**说明**：现有「点击看原卷」的入口有三处——总览词条的「出自原卷」缩略图（`Overview.tsx` → `CropImage`）、看板抽屉里的题目卡片（`QuestionCardView`）、报告引用 `[卷名 · 题号]` 的卡片（`MarkdownView`）；审核页另有「画框」（`BoxEditor`）。报告人没说是哪一处，需要先问清（列入验证步骤）。

**数据流**：题目 `page_idx` + `bbox_json` + 页面行 `pages.image_rel` → SQL 里 `LEFT JOIN pages pg ON pg.paper_id = q.paper_id AND pg.idx = q.page_idx`（`stats/core.ts`、`stats/analysis.ts`）→ 渲染端 `CropImage` 用 `ewb://page/<paperId>/<page-N.png>` 加 CSS 定位显示；导出用 `report/export.ts` 的 `cropForRef`。任何一环为空，用户看到的就是「没有截图」。

**可能原因与条件**（由高到低，均为**推测**，附验证办法）：

| # | 条件 | 现象 | 判断办法 |
|---|---|---|---|
| 1 | **试卷是 Word（docx）**：`extractDocx` 写入的页记录 `image_rel=''`、宽高 0、没有坐标行，所以 `pageRel` 恒为 null | `CropImage` 显示「没有原卷页面图（Word 试卷或页面未生成），无法截图」；报告导出里引用后没有图 | `SELECT text_source, image_rel FROM pages WHERE paper_id=?` 看是否 `docx` / 空 |
| 2 | **定位失败**（`bbox_source='none'`，`bbox_json` 为空）：文本锚点对不上（Windows 缺中文包导致锚点乱码、扫描质量差、模型给的 `anchor_ref` 错） | 不是裁剪而是显示整页缩略图并注「这道题没有定位框」；`OriginExample` 在有 bbox 的题里优先挑，全无时退回整页 | `SELECT bbox_source, count(*) FROM questions WHERE paper_id=? GROUP BY 1`；审核页看题目是否有「框」标记 |
| 3 | **`page_idx` 为空或对不上**：JOIN 取不到页 → `pageRel` 为 null | 同 1 的提示，但试卷明明是 PDF | `SELECT count(*) FROM questions WHERE paper_id=? AND page_idx IS NULL`，或 `page_idx` 不在 `pages.idx` 里 |
| 4 | **页面图文件不存在或打不开**：失败时 `removeDerivedFiles` 清了；重新提取后文件未生成；数据目录在外置盘 / 网络盘且当前未挂载；数据包导入时文件没拷全 | 图片裂开（`ewb://` 返回 404），或空白 | 主进程日志（新增日志后）里 `ewb://` 的 404；手工看数据目录 `files/<paperId>/page-N.png` |
| 5 | **框被「墨迹修准」或旧版缩框改坏**：启动时 `refineAllOnce()` 会按页面像素重新修每题的框（`parse/ink.ts`），v10 迁移也缩过邻题的右边；裁切现在 `PAD_X = PAD_Y = 0`（`shared/crop.ts`），框紧贴文字。扫描件有阴影 / 倾斜时可能收得太紧或太小 | 截图只有半行字、被截掉选项，用户感觉「截不对」 | 查 bbox 面积分布：`bbox` 宽 < 0.05 或高 < 0.01 的题数；对比 `bbox_source='manual'` 的 |
| 6 | **Windows 路径检查**：协议处理 `protocol.ts` 用 `resolved.startsWith(filesDir + path.sep)` 判断路径穿越；盘符大小写、符号链接、短路径（8.3）不一致时会返回 403 | 所有图都不显示 | 日志里 `ewb://` 的 403；数据目录若被用户改到 `d:\…`，看 `getFilesDir()` 与实际路径的大小写 |
| 7 | **安全策略**：渲染端 CSP 的 `img-src` 含 `ewb:`（`index.html`），协议也在 `registerSchemesAsPrivileged` 里登记（`main/index.ts`），所以一般不是原因；若自动更新 / 单实例改动动过协议注册时机，可能出现 | 全部图都不显示 | 开发者工具控制台看 CSP / 协议错误 |
| 8 | **用户指的其实是审核页画框**：docx 没有页面图，审核页根本画不了框 | 审核页「在此页画一个框」无效 | 询问报告人 |

**修复与改进设计**：

1. **把「为什么没有截图」说清楚**：`CropImage` 的空态按原因区分——Word 文件、没有定位框、页面图丢失、页码对不上，各给一句白话 + 可做的事（Word：「Word 文件没有页面图。可以导入同一份卷子的 PDF 来获得原卷截图」；没有框：「去审核页画一个框」；图丢失：「原图找不到，请检查数据目录是否可用」）。
2. **Word 试卷的替代展示**：在截图位置显示「题目卡片」——用库里的题干和选项排成接近试卷的样子，标明「Word 无原卷版式，显示的是识别出的题干」。（用 mammoth 的 HTML 渲染成近似版式图是后续选项，版式不可靠，不作为本里程碑承诺。）
3. **自检按钮**：试卷详情里「截图自检」：「38 道题里 31 道有截图。7 道没有：5 道没有定位框、2 道页面图找不到」，每类给修复入口。诊断包里记录同样的计数（不含内容）。
4. 保留对 5 的保险：`refineAllOnce` 改完框之后，若新框面积小于原框的 40%，不覆盖并记日志。
5. 验证流程：先在报告人机器上让他导出诊断信息（含上述计数），再决定是 1 / 2 / 4 哪一类，不盲改。

**测试**：单测——空态原因枚举函数（输入页记录和题记录 → 原因）；`cropForRef` 对缺图、越界 bbox 的行为；墨迹修准的保险。E2E——docx 试卷的引用显示卡片而不是裂图；删掉一个页面文件后显示「页面图找不到」。**工作量**：调查 0.5 天 + 修复约 2.5 天。

## 5　功能 E：诊断信息与批量提速

### 5.1　运行日志（现在没有）

**现状**：主进程只用 `console.log/warn`（散落在 `db.ts`、`queue.ts`、`index.ts` 等），打包后看不到；渲染端错误不记录；崩溃无记录。

**设计**：

- 新模块 `src/main/log.ts`：写到 `app.getPath('logs')` 下（Mac `~/Library/Logs/卷知`，Windows `%APPDATA%\卷知\logs`），**不写在可迁移的数据目录里**（日志属于这台电脑）。文件 `juanzhi-YYYY-MM-DD.log`，单文件 ≤ 2 MB，最多保留 7 天或 10 个文件，滚动写；写入失败静默降级，不影响业务。
- 接管主进程的 `console.*`（保持原输出），统一格式：`时间 级别 标签 消息 {json 字段}`。
- 记录：启动 / 退出、版本与平台、迁移、导入与提取（试卷用 **8 位短 id**，不记标题和文件名）、OCR（识别方式、语言、耗时、退出码）、解析每批（模型、模式、页数、尝试、截断、耗时、token、错误码）、AI 调用（只记元数据，**绝不记提示词、响应正文、密钥**）、IPC 异常、`render-process-gone` / `child-process-gone` / `uncaughtException` / `unhandledRejection`、渲染端错误（`window.onerror` 与未处理的 Promise 拒绝经 `log:renderer` 通道上报，限速每分钟 30 条）。
- **脱敏**：沿用 `ai/guard.ts` 的 `redact`（去 `sk-…`、`Bearer …`、当前密钥）；路径里的用户名替换为 `~`；URL 只留主机名。
- 日志级别：一般（默认）/ 详细（含请求大小、批次明细）。开关在设置 → 管理员设置。
- 测试：单测——滚动与保留、并发写、脱敏（喂入含密钥 / 路径 / 标题的行，断言输出不含）；E2E——触发一个已知错误后日志里能找到对应标签。

### 5.2　「导出诊断信息」

入口：帮助菜单、设置 → 关于。点击先弹**预览对话框**，列出将包含的内容和大小，并明确写出**永远不包含**的东西，用户确认后生成 zip（jszip）。

**默认包含**（不含学生数据、不含密钥）：

- `README.txt`：这是什么、包含什么、怎么发给开发者（附到 GitHub Issue，不会自动上传）；
- `summary.json`：卷知版本、系统与架构、Electron / Chromium / Node 版本、内存、数据盘剩余空间、界面语言、是否检测到代理环境变量（只有 true/false）、schema 版本、数据目录是否在外置盘；
- `config.json`：服务商预设 id、拆题 / 报告 / 视觉模型名、`vision_policy`、并发数、Base URL **仅主机名**、密钥「已设置 / 未设置」（绝不含内容）；
- `ocr.json`：OCR 状态（引擎、语言）；
- `papers.csv`：每份卷子一行（短 id、状态、页数、各页识别方式计数、识别语言、是否有「识别可能不完整」、各阶段耗时、批次数与重试数、错误码——**不含标题、文件名、错误原文里的题干**）；
- `ai-usage.csv`：按模型和类型汇总的调用数 / 失败数 / token；
- `logs/`：最近 7 天日志（已脱敏）；
- `checks.json`：一键自检的结果（见 5.3）。

**需要用户主动勾选才包含**：

- 「包含试卷标题和文件名」（可能含学校 / 学生姓名，勾选时给出警告）；
- 「包含某几份卷子的页面图和识别原文」（逐份选择，供开发者复现识别问题；勾选时警告并预览缩略图）。

**永远不包含**：API Key、完整 Base URL、题目内容、报告内容、课程大纲内容、学生姓名。

另提供「复制简短诊断」：5 行文字（版本、系统、AI 服务商与模型、OCR 引擎语言、是否有视觉模型），粘贴到 GitHub Issue 即可。

测试：**生成一个包含假密钥、假标题、假题干的数据库的诊断包，解压后全文搜索这些字符串必须找不到**（黄金测试）；勾选项生效的对照用例；zip 结构。

### 5.3　一键自检（给用户和开发者的第一步）

设置 → 关于 →「一键自检」，逐项显示通过 / 不通过 / 建议：数据目录可写与剩余空间、数据库 `quick_check`、OCR 引擎与语言、各模型连通测试（需点击，花极少量用量）、到 Base URL 主机的网络可达（含代理提示）、系统时间是否明显错误（影响 HTTPS）、字体（中文导出）。结果同时写进诊断包。

### 5.4　大批量提速

**先量再改**：用 `test:perf` 与 `test:real-ai` 在真实服务商上测出各环节耗时占比（OCR / 排队 / AI 拆题 / 定位入库），再动手；下面的设计按「预期收益 / 风险」排序。

1. **并发上限 4 → 20，且自适应降速**（beta.1）：
   - `concurrency` 范围改为 1–20，默认保持 2；设置里提示「并发越高越快，但服务商可能限速（429）」；
   - 新增全局「AI 并发闸」：所有 AI 调用（解析、报告）共用的令牌池，容量 = 当前有效并发；
   - **AIMD 自适应**：遇到 429（`rate_limit`）→ 有效并发减半（最少 1）并冷却 30 秒（尊重 `Retry-After`）；连续 N 次成功 → 有效并发 +1，直到用户设定的上限；队列页显示「服务商限速，已自动降到 3 路」；
   - 与现有客户端的指数退避重试协同：429 仍由 `chat()` 退避，闸只负责降低新请求的发出速度。
2. **拖入文件夹**（beta.1）：`papers:import` 接受目录路径；主进程递归扫描（深度 ≤ 3、最多 500 个文件），只收 `.pdf .jpg .jpeg .png .heic .docx`，跳过 `._*` 与隐藏文件，导入前显示「发现 N 个文件，将跳过 M 个（原因）」确认；目录路径经 `getPathForFile` 授权，其下文件视为已授权；现在 `PathsSchema` 限制 100 个，改为分批提交。
3. **解析期间防止电脑睡眠**（beta.1）：`powerSaveBlocker.start('prevent-app-suspension')`，在提取队列或解析队列有任务时开启，空闲时关闭，并在队列页显示一句「解析期间电脑不会自动睡眠」。注意：合上笔记本盖子仍会睡眠，文案要说清楚。
4. **Windows 提取慢**（beta.1 先测，是否做看数据）：现状是每页都新起一个 `powershell.exe`、重新加载 WinRT 类型（启动开销可能占大头），且提取队列是严格串行。方案：提取队列并发 2–3；把 `ocr.ps1` 做成常驻进程，通过标准输入收图片路径、逐行输出 JSON（一个进程服务整批页面）。收益需实测，列为条件项（约 2 天）。
5. **一份卷子内多批并行**（**不进 beta**，实验）：现在后一批依赖前一批的 `PREV_CONTEXT`（跨页续题）。而大多数卷子 2–4 页、`batch_pages=3`，往往只有 1–2 批，并行收益有限。真要做：两阶段——并行拆各批（上下文留空），再用 `continues_next` 标记做确定性拼接；用 `test:real-ai` 对比串行结果的题数 / 知识点一致率，≥ 98% 才允许打开，默认关，设置里叫「快速模式（实验）」。放在 1.3.0 之后。

测试：单测——AIMD 控制器（429 降、成功升、冷却、上下限）、目录扫描（深度、数量、过滤、隐藏文件）、防睡眠开关的状态机；E2E——mock 返回连续 429 → 有效并发下降且最终全部成功；拖入含 30 个文件的文件夹。

工作量：并发闸 + AIMD 2 天；文件夹 1 天；防睡眠 0.5 天；Windows OCR 优化 2 天（条件）；实验并行 3 天（后续）。风险：并发过高触发服务商封号 / 余额快速消耗（缓解：默认不变、上限提示、AIMD、用量页可见）；文件夹里混入大量无关文件（缓解：确认对话框）。

## 10　测试策略汇总

- **单元测试**：见各节清单，全部加入 `package.json` 的 `test:unit` 链。新增的纯函数一律放在不依赖 electron 的模块（`src/main/course/*.ts`、`src/shared/*.ts`），便于 `node --experimental-strip-types` 直接加载。

- **真实 AI**（`npm run test:real-ai`，需要用户自己的密钥，不进 CI）：拆题模型对比（D3）、课程匹配质量抽查（用虚构大纲）、变形题正确率人工抽样（至少 20 题）、话术合规抽查。

- **手工 / 验收清单**：Word、WPS、Pages 打开导出的 docx（含卡片）；PDF 中文字体；投屏下的看板「课程对照」可读性（大字、对比度、颜色旁有字）。
- **回归红线**：现有 E2E（M1–M8）与全部单测必须保持通过；事实核对、家长版门槛、`ipc-guard-audit`、`prompts-sync`、`packaging-config` 不得被改弱。

# 补充：「出自原卷」截不到具体题（2026-11-02 用户反馈，并入 beta.1）

现状（读代码确认）：
- 截图位置来自「本机识别出的每行文字的位置 + AI 给的题目开头」对齐（`parse/locate.ts`）；对不上时这道题 bbox = null，标「没找到位置」。
- 总览「出自原卷」（`Overview.tsx` OriginExample）在这个知识点的题都没有 bbox 时，退回显示**整页**——看起来就像「截不到题」。用户截图正是这种情况（一张图里是整页试卷）。
- 图片 / 截图上对不上的常见原因：本机识别质量差（Windows 没装中文语言包时中文变乱码，AI 给的题目开头在识别文字里找不到）、整页走了视觉模型而视觉模型没给出框、推理模型给的开头不准。
- Word：`extractDocx` 不生成页面图（imageRel 为空），所以 Word 试卷**根本没有原卷图可截**。

方案：
1. 总览和其他用到原卷截图的地方：没有框时不再显示整页冒充这道题；显示「这道题还没在原卷上框出位置」+「去框一下」（跳到审核页这道题，手动画框后立即生效）。
2. 图片 / 截图定位成功率：随 beta.1 的 Windows 识别质量判断一起修（质量差的页交给视觉模型，并要求视觉模型返回每道题的框）；解析完成后在试卷详情里显示「N 道题没找到位置」并一键跳去框选。
3. Word 也有原卷图：用隐藏窗口把 Word 内容（mammoth 转出的 HTML，保留编号、下划线、表格）按 A4 宽度排版并截成页面图，同时用 DOM 取每行文字的位置写进 lines_json——之后和图片走同一套定位和截图。顺带改善 Word 编号 / 下划线丢失导致的拆题不准（设计稿 D4）。
4. 测试：PNG、手机照片、Word 各一份夹具，断言解析后 ≥90% 的题有框、总览截图是题目区域而不是整页；Windows CI 上跑 Windows 识别版本。
