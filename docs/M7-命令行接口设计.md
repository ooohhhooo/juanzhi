# M7 命令行接口（CLI）设计

目标版本 1.2.0。让 Agent（Codex、Claude Code、WorkBuddy 等能执行命令的助手）和个人用一行命令调用卷知，做到「导入试卷 → 等解析 → 看统计 → 生成报告 → 导出文件」。

## 1. 总体做法

**同一个程序，加 `cli` 子命令**：打包后的可执行文件收到第一个参数 `cli` 就进入命令行模式，不新增第二个程序。

```
Mac      "/Applications/卷知.app/Contents/MacOS/卷知" cli status
Windows  "<安装目录>\EnglishExamWorkbench.exe" cli status
短命令   juanzhi status          （设置 → 管理员设置 → 「安装命令行工具」写入）
```

命令行模式下：
- **不创建任何可见窗口**，不弹任何对话框；macOS 调 `app.dock.hide()` 和 `setActivationPolicy("accessory")`，运行期间没有可见的 Dock 图标（进程刚启动的最初几百毫秒可能闪一下，因为这两个调用要等应用初始化）。导入 PDF 需要一个**看不见的离屏渲染窗口**（`show:false`，和图形界面导入时是同一个），没有 Dock / 任务栏图标，也不会闪一下。
- 不注册应用菜单，不创建主窗口，不加载界面。
- 主进程里已有的 `console.log` 之类全部改写到 stderr，保证 stdout 干净。

## 2. 复用现有逻辑（不另写一套）

主进程的业务逻辑今天都在各个 `ipcMain.handle(…)` 处理函数和它们调用的 service 里（导入队列、解析队列、统计、报告生成、事实核对、家长版把关、busy 守卫……）。命令行模式**把这些处理函数原样注册进一个内存表**（临时替换 `ipcMain.handle`），命令实现直接按通道名调用它们：

```
invoke('stats:overview', filter)  →  同一个处理函数、同样的 zod 参数校验、同样的 service
```

所以界面上生效的守卫在命令行里**一样生效**：参数校验、事实核对、家长版「我已核对」把关、样本不足提示、内部代码过滤、`busy.ts`。只有两处不能照搬（要弹系统对话框 / 要读剪贴板）：`report:export` 的「另存为」，所以把导出的核心抽成函数 `exportReportFile()`，界面和命令行共用；其余按通道调用。

不注册的模块：数据包导入导出（`data:*`）、`ai:*`。已注册的处理函数里还有不少写入类通道（`papers:remove`、`questions:*`、`taxonomy:*`、`report:delete` ……）——它们**注册了但不可调用**：`run.ts` 里有一份写死的通道白名单（`CLI_ALLOWED_CHANNELS`：`ocr:status`、`papers:list/get`、`questions:list/confirmPaper`、`stats:overview/hot/compare`、`report:generate/list`），其余通道一律拒绝。

## 3. 输出约定

- **stdout 只有一段 JSON**（单行，UTF-8，末尾一个换行）。成功 `{"ok":true,"data":…}`；失败 `{"ok":false,"code":"…","message":"中文白话","exit":N}`。
- **进度和日志写 stderr**，每行以 `[juanzhi]` 开头，Agent 可以忽略。
- `--out <文件>`：把同样的 JSON 同时写进文件。**例外**：`report export` 里 `--out` 是导出文档的路径（规范里就是这么定的），JSON 想另存为文件用 `--result-file <文件>`；`--result-file` 在所有命令里都可用，Windows 的 `juanzhi.cmd` 就靠它回读结果。
- 输出是**纯 ASCII**：所有非 ASCII 字符写成 `\uXXXX`（仍是合法 JSON），Windows 控制台按任何编码解码都不会乱码。
- 结果文件的安全：不能写进数据目录 / userData，扩展名只能是 `.json` / `.txt` / 无扩展名，已存在的文件必须是卷知以前写的结果文件，不跟随符号链接，写在关闭数据库之后；环境变量 `JUANZHI_RESULT_FILE` 指定的文件旁边还会写一个 `.exit` 文件（只有退出码），Windows 包装脚本靠它取退出码。`report export --out` 目标已存在时默认拒绝，要 `--overwrite`。
- 其他全局参数：`--timeout <秒>`（`--wait` 的上限，默认 3600）、`--quiet`（不写 stderr 进度）。

### 退出码

| 码 | `code` | 含义 |
|---|---|---|
| 0 | — | 成功 |
| 1 | `internal` | 没预料到的内部错误（message 里有原因） |
| 2 | `usage` | 命令或参数不对（缺参数、未知命令、筛选值非法） |
| 3 | `app_running` | 卷知窗口正在运行：请先关闭卷知窗口再用命令行 |
| 4 | `cli_busy` | 另一个命令行任务正在使用数据：等它结束后重试 |
| 5 | `ai_not_configured` | 没配 AI：请到界面「设置 → AI 服务」里填写（命令行不能设置 API Key） |
| 6 | `not_found` | 试卷 / 报告 id 不存在，或文件不存在 |
| 7 | `invalid_state` | 当前状态不允许（试卷还没解析完、范围内没有已确认的试卷、报告已过期……） |
| 8 | `confirmation_required` | `papers confirm` 没带 `--i-reviewed` |
| 9 | `import_failed` | 一份或多份文件没能导入 / 提取 / 解析（`data` 里有每份的结果） |
| 10 | `timeout` | `import` 等待超时（命令行进程退出后没处理完的任务不会继续：卷子退回「已提取」或标失败，到窗口的处理队列里重试） |
| 11 | `export_blocked` | 导出被拦（家长版没通过把关：内容太少 / 有矛盾句等） |
| 12 | `busy` | 现在有别的后台任务（提取 / 解析 / AI）占着数据，稍后再试 |
| 13 | `data_unavailable` | 数据目录不可用或数据库打不开 |
| 14 | `ai_failed` | AI 服务调用失败（网络、密钥无效、额度等；message 里是白话原因） |

## 4. 命令（第一版）

| 命令 | 作用 |
|---|---|
| `status` | 版本、数据目录、卷子数（按状态）、AI 是否已配置（只说有没有，绝不输出密钥）、OCR 是否可用 |
| `import <文件…> [--wait]` | 导入并自动提取 + AI 解析，返回每份的结果。提取和解析是在命令行进程里做的（排队的任务存在进程内存里），所以命令**总是**等到每份进入「待审核」或失败才返回——不加 `--wait` 也一样（保留 `--wait` 是为了让 Agent 的写法更明确）；`--timeout <秒>` 限制最长等待 |
| `papers list [筛选] [--status s]` | 试卷列表 |
| `papers show <id>` | 试卷信息 + 题目（题型、分值、知识点、难度、是否已确认） |
| `papers confirm <id> --i-reviewed` | 跳过人工审核、直接确认整份（见 §6 风险） |
| `stats overview / hot / compare` | 和界面一致的统计；`hot` 可加 `--level 1|2|3`；`compare` 要 `--target <学年> [--base before|<学年>]` |
| `report generate --reader boss\|teacher\|parent\|full [筛选]` | 生成报告，返回 `reportId`、`markdown`、`unverified`（未核实的句子）、`warnings`、`draft` |
| `report list` / `report show <id>` | 报告列表 / 详情 |
| `report export <id> --format md\|docx\|pdf --out <路径>` | 导出文件（见 §6） |

筛选参数（stats / report / papers list 通用）：`--grade 1-6`、`--semester 上|下`、`--year <学年起始年>`、`--exam-type 单元测试|期中|期末|月考|其他`、`--textbook <名称>`、`--region <名称>`、`--include-reviewing`（把待审核的卷子也算进去）、`--include-duplicates`。

## 5. 并发与互斥

「谁在使用数据」靠一个**系统级的锁**判断（不靠 Electron 的单实例锁：后者会把「第二个实例」的信号发给窗口、让窗口抢焦点；也不靠 pid 写在文件里：崩溃、断电后 pid 会被别的进程复用，锁文件会永远不过期）：

- 锁 = 一个**监听中的本地套接字**（Windows：命名管道；Mac：userData 里的 unix 套接字，路径太长时用 /tmp 下按目录哈希命名的）。**谁在监听谁持有**，进程死了（崩溃、强杀、断电）系统自动释放，没有陈旧锁、没有 pid 复用。持有者在别人连上来时回一行 `{pid, mode, startedAt}`，对方据此知道是窗口还是命令行、是哪个进程。
- 抢锁、探测、清理崩溃后留下的陈旧套接字文件，全部在一个「守卫目录」（`mkdir` 原子）里串行进行，所以不会出现「删掉别人刚建好的锁」；守卫 10 秒后视为过期。
- 沙箱不让监听本地套接字时退回「锁文件」：用 `link` 原子地带着完整内容创建，陈旧判断 = pid 不在或启动时间早于本次开机，清理同样在守卫里。
- 图形界面启动时加锁（`mode: gui`）；命令行启动时加锁（`mode: cli`）。
- **命令行遇到窗口在运行** → 退出码 3，「请先退出卷知再用命令行」（Mac 上只关窗口不等于退出，要 Cmd+Q）。
- **两个命令行同时跑** → 第二个退出码 4（报错，不排队），message 带对方的进程号。
- **命令行运行时打开窗口** → 窗口弹出提示（带对方的进程号），按钮「好」和「结束命令行任务并打开」（给卡住的命令行用，会结束那个进程）；自动化环境用 `EWB_NO_DIALOG=1` 改成写 stderr + 退出码 3。
- 数据目录只能用已有的环境变量 `EWB_USER_DATA_DIR` 指定（测试用）；没有任何参数能改数据目录。

## 6. 安全边界

- **API Key**：命令行不能设置、不能读取。`status` 只返回 `aiConfigured: true|false`。没配 AI 时 `import` / `report generate` 报 `ai_not_configured`。
- **不能删除**试卷或报告（第一版没有删除命令）。
- **`papers confirm`**：把整份试卷所有题标为「已确认」，等于跳过人工审核。AI 解析会有错（题型、分值、知识点都可能错），这些错会直接进入统计和报告。所以必须显式带 `--i-reviewed` 才执行；没带就退出码 8，并提示「应该在卷知界面里审核」。使用者（或 Agent）加这个参数，就等于声明「我已经审核过了」。
- **家长版**：命令行**不提供**替家长版点「我已核对」的命令。`report export` 导出家长版时，如果界面里没点过「我已核对」：
  - 文件开头有醒目的引用块 `> **AI 草稿 · 未经老师核对，请勿直接发给家长**`（Markdown / Word / PDF 都有），页脚仍写「AI 草稿 · 请老师核对后再使用」，未核实 / 矛盾的标记保留；
  - 返回的 JSON 里 `data.draft: true`、`data.warning: "AI 草稿 · 未经老师核对…"`。
  - 家长版本身没通过把关（内容太少、有未能删掉的矛盾句、超过 300 字）时仍然拒绝导出（退出码 11）。
- **未核实的句子**：`report generate` / `report show` 的 `data.unverified` 列出所有事实核对没通过的句子，Agent 应该转告用户，不应当自己「删掉就算处理」。

## 7. Windows：怎么拿到输出和退出码

Electron 在 Windows 上是 GUI 子系统程序：从 cmd / PowerShell 直接运行 `…exe cli …` 时，shell **不会等它结束**，也不会拿到它的 stdout 和退出码。所以：

1. **`juanzhi.cmd`（推荐）**：包装脚本用 `start "" /wait "<exe>" cli %* --result-file "%TEMP%\juanzhi-<随机>.json"` 同步等待，然后 `type` 把结果文件打到 stdout，`exit /b` 返回进程的退出码（`ok:false` 但进程码为 0 的情况——例如免安装版的启动器不传递退出码——按 `exit` 字段补）。cmd 和 PowerShell 里调用 `juanzhi …` 都是同步的，都能读到 stdout 和 `$LASTEXITCODE` / `%ERRORLEVEL%`。
2. **直接调用 exe**：加 `--result-file`（或 `--out`）把 JSON 写进文件，用 `Start-Process -Wait -PassThru` 等待并取 `ExitCode`，再读文件。文档里给了 PowerShell 和 cmd 的完整示例。stdout 在被管道 / 重定向接住时也能写出来（Windows CI 实测，结果见文档）。
3. 不能做的：让 GUI 子系统的程序「附着父进程控制台」需要原生模块（`AttachConsole`），本项目不带原生模块，所以不用这条路。

**退出码以结果文件为准**：包装脚本取 `.exit` 文件里的码（程序写完结果之后异常退出、或免安装版的外层启动器不传递退出码时，调用方仍然拿到正确的码）。直接调用 exe 时 JSON 里的 `ok` / `exit` 是准确的。

**免安装版（portable）的限制**：portable 每次启动都会先解压到临时目录再运行，所以命令行启动要多花几秒；包装脚本指向 `PORTABLE_EXECUTABLE_FILE`（portable 文件本身的位置），**移动或删除这个文件后短命令会失效**；portable 的外层启动器不一定传递退出码，包装脚本因此以结果文件里的 `ok / exit` 为准。要长期给 Agent 用，建议装安装版。

## 8. 「安装命令行工具」

设置 → 管理员设置里的按钮，调用主进程 `cli:install`：

- **Mac**：写 `~/.local/bin/juanzhi`（`#!/bin/sh` + `exec "<当前 .app 里的可执行文件>" cli "$@"`），`chmod 755`。**安全**：目标已存在时，符号链接拒绝（不写穿）、不带「JUANZHI-SHIM」标记的文件拒绝（不覆盖用户自己的 juanzhi），自己写的才替换，临时文件 + 改名。PATH 提示：先问用户的登录 shell（`zsh -ilc`），已经在 PATH 里就不提示；不自动改 shell 配置文件。
- **Windows**：写 `%LOCALAPPDATA%\Juanzhi\bin\juanzhi.cmd`（同样的覆盖规则），并把这个目录加进**用户级** PATH：**直接读写注册表** `HKCU\Environment\Path`，原样保留类型（REG_EXPAND_SZ）和里面的 `%变量%`（不展开），只在末尾追加；追加前把原值备份到 `%LOCALAPPDATA%\Juanzhi\path-backup.txt`，写完广播 `WM_SETTINGCHANGE`。不需要管理员权限；做不到时只提示手动添加。Windows CI 里有一条真实用例：先写入带 `%USERPROFILE%` 的 REG_EXPAND_SZ，装完后断言类型不变、原值逐字符不变、只多一个目录。
- 目标程序路径取当前运行的可执行文件（安装版）或 `PORTABLE_EXECUTABLE_FILE`（免安装版，界面上提示限制）。从 dmg 挂载盘（`/Volumes/…`）或「下载」文件夹里直接打开（App Translocation 的临时路径）时拒绝安装，要求先拖进「应用程序」。
