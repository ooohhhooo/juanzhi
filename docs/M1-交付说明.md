## 1. 技术栈（实际安装版本）

Electron 45.0.0（Node 24，内置 `node:sqlite`，**无任何原生模块**）· React 19.3.1 · antd 6.6.7 · electron-vite 6.0.0 / vite 6.4.5 · TypeScript 5.9.3 · pdfjs-dist 4.10.38 · mammoth 1.13.0 · zod 3.25.76 · @tanstack/react-query 5.104.5 · react-router-dom 7.18.4。
开发依赖新增 `playwright-core 1.64.1`（只用来驱动真实 Electron 做 E2E，不下载浏览器）。已移除 `uuid` / `@types/uuid`（改用 `crypto.randomUUID()`）。

## 2. 怎么跑

```bash
export npm_config_cache=$TMPDIR/npmcache
npm run dev          # 开发
npm run build        # 构建 main / preload / renderer
npm run typecheck    # node + web 两套 tsconfig
npm run test:e2e     # 构建后用 playwright-core 启动真实 Electron，跑 34 项检查（需在沙箱外）
bash scripts/build-ocr-mac.sh   # 重新编译 macOS OCR 通用二进制（arm64+x86_64）
```

数据目录固定为 `~/Library/Application Support/english-exam-workbench/workbench-data/`（Windows：`%APPDATA%\english-exam-workbench\workbench-data\`），`dev`、`build` 后运行、`electron .` 等任何启动方式都一致。
环境变量 `EWB_USER_DATA_DIR` 只给自动化测试隔离数据用，正常使用不要设置。

## 5. Windows OCR 脚本（⚠️ 从未在 Windows 上运行）

`native/windows/ocr.ps1`：PowerShell 5.1 + `Windows.Media.Ocr`。要点：UTF-8（带 BOM，PS 5.1 才不会按 GBK 读坏中文）输出无 BOM JSON；正则用 `\uXXXX` 转义；语言先 `zh-Hans-CN`，没有则退到用户语言，都没有退出码 3（主进程译成「未安装 OCR 语言包」）；行文本取 `OcrLine.Text`（保留英文单词间空格）并去掉汉字间空格；坐标由 `Words.BoundingRect` 合并后归一化；置信度固定 0.8（系统不提供）；超过 `MaxImageDimension` 报错。
这个脚本是照着评审的要点和 API 文档写的，**没有任何运行验证**；错误最可能出在 WinRT 异步等待（`AsTask` 反射）和类型加载上。人工验收清单：Win10 1809+/Win11 上 `powershell -NoProfile -ExecutionPolicy Bypass -File native/windows/ocr.ps1 samples/g4-2025-page1.png` 应在 stdout 只输出一段合法 JSON，行数 > 30，中文无乱码。
