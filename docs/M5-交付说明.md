# M5 交付说明：打包、打包后验证、CI、安装指南，以及 M4 转入的项

> 范围：electron-builder 打包（Mac dmg × 2、Windows NSIS + portable）、占位图标、打包后验证（打包版冒烟 E2E、产物检查脚本）、GitHub Actions 工作流（只写文件）、安装指南（文档 + 应用内页面）、Windows 手工验收清单、M4 三审转入的 P2 项。
> 图例：✅ 已验证（写明验证方式）；⚠️ 没有验证或只验证了一部分（写明原因和手工验证方法）；❌ 未做。
> 本轮**没有做任何 git 写操作**（没有 add / commit / push，没有创建仓库），没有改 v1–v9 迁移，没有改 `docs/prompts/*`，没有写 Claude memory，没有调用真实 AI（全程 `tests/mock-ai`，端口随机，不占用户的 18080），没有碰 `~/Library/Application Support/` 下本应用的目录（E2E 和冒烟都用临时 userData），没有安装到 `/Applications`。
> **最要紧的一句话：Windows 上没有运行过任何东西。** Windows 安装包只在 Mac 上交叉打出来并做了静态检查；NSIS 安装器、portable、ocr.ps1、Windows 分支的冒烟、GitHub Actions 工作流都没有真正跑过。`docs/Windows验收清单.md` 是留给真实 Windows 电脑的。

## 1. 怎么打包、怎么验证

```bash
export npm_config_cache=$HOME/.ewb-npmcache      # 随意，只要不是沙箱外不可写的位置
npm ci
npm run typecheck && npm run test:unit            # 27 组单测
npm run dist:mac        # Mac：两个 dmg（arm64、x64），ad-hoc 签名
npm run dist:win        # Windows：NSIS 安装包 + portable（可以在 Mac 上交叉打，不需要 Wine）
npm run dist            # 两个都打
npm run verify:artifacts                         # 检查 release/ 里的产物（40 项）
node tests/e2e/smoke-packaged.cjs                # 打包版冒烟（自动找本机刚打的包；EWB_APP_EXE 可指定）
npm run icons                                    # 重新生成占位图标（换图标时：替换 build/icon.png 后运行）
```

- 打包需要联网（下载 Electron 的 darwin-x64 / win32-x64 压缩包、NSIS、dmgbuild 等，都从 GitHub 下载，本机试过可直连；连不上时可设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`，我这次没有用到）。**沙箱外、unset 代理变量**。
- **输出目录**：默认 `release/`（已加进 `.gitignore`）。这台电脑的项目在 **exFAT 移动硬盘**上：Mac 的 `.app` 框架全是符号链接、exFAT 又会给每个文件生成 `._xxx`（electron-builder 会把 `._app.asar` 当成 asar 去读，直接崩溃——我第一次打包就是这么挂的）。所以 `scripts/dist.cjs` 在 macOS 上检测到这种磁盘时会自动改在 `~/.ewb-build` 里打包，最后把 dmg / exe 拷回 `release/`。环境变量 `EWB_BUILD_DIR` 可指定别处。用户那边的试用副本如果在同一块盘上，同样适用。
- `scripts/dist.cjs` 用 `node <包里的 bin 脚本>` 调用 electron-vite 和 electron-builder（不走 `.bin/` 里的 shell 脚本，Windows 上那是 `.cmd`，直接 spawn 会失败）。⚠️ 这一点只在 Mac 上跑过。

**为什么 Mac 做两个 dmg 而不是 universal：** 每个包小一半左右（universal 约 200+ MB），下载快；代价是老师要选对架构。安装指南第一部分写了怎么看（苹果菜单 → 关于本机）、并说下错了只是打不开不会损坏电脑。如果你更想要「一个文件通吃」，改 `electron-builder.config.cjs` 里 `arch: ['universal']` 即可（OCR helper 本来就是通用二进制，不用改别的）——见 §7 需要确认。

## 5. 已定的决定与实现取舍

- **Mac 两个 dmg，不做 universal**（理由见 §3）。
- **Windows 安装包默认装给当前用户**（`perMachine: false`）：老师电脑多半没有管理员权限。向导里仍会有「为谁安装」一页（默认「仅为我」，不要管理员密码；选「所有用户」才要，指南和验收清单都写了）。默认安装目录是 `%LOCALAPPDATA%\Programs\EnglishExamWorkbench`（**ASCII**，取自 `win.executableName`，不是中文产品名；审核指出我原先写成了中文目录，已更正）。可改安装目录；桌面和开始菜单快捷方式是自动创建的。
- **可执行文件名用 ASCII，显示名用中文**：Windows exe 是 `EnglishExamWorkbench.exe`（`win.executableName`），快捷方式、安装器标题、「应用」列表里显示「英语校考分析工作台」；Mac 的 `.app` 直接叫「英语校考分析工作台.app」。产物文件名全是 ASCII，免得下载 / CI 上传遇到中文文件名问题。
- **Mac 最低系统 13.0**：`ocr.swift` 本来就是为 macOS 13 编译的（中文识别需要）；Electron 45 本身的下限不是瓶颈。
- **不重建原生模块**（`npmRebuild: false`）：本应用没有原生模块；同时排除 pdfjs-dist 的可选依赖 `@napi-rs/canvas`（只给 Node 里渲染用，我们的 pdf.js 跑在渲染进程里）。
- **冒烟里的 mock AI 用随机端口**：`startMock({ port: 0 })`，和用户终端里可能开着的 18080 共存，没有杀任何进程（另外 M1–M4 套件本来就是随机端口）。
- **`EWB_USER_DATA_DIR` 在打包版里同样有效**（M1 起的测试开关）：普通使用不会设置；冒烟靠它把数据放进临时目录。
- **portable 版**是 electron-builder 的 NSIS 自解压：每次启动先解压到临时目录，所以启动会比安装版慢几秒，数据仍在同一个 `%APPDATA%\english-exam-workbench`（指南和验收清单都写了）。
- **ad-hoc 签名的钥匙串副作用**（已知的 macOS 行为，⚠️ 没有实测）：ad-hoc 签名的指定要求绑定在代码哈希上，所以**每次升级到新版本后，钥匙串对「始终允许」的记忆会失效，第一次读取已保存的密钥时会再弹一次授权框**。点「拒绝」不会坏数据，只是密钥读不出来、需要重新填（代码里 `getApiKey` 解密失败就当没有密钥）。安装指南里已写。要彻底避免需要付费的 Apple 开发者证书。
