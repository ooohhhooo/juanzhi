## 1. 怎么跑

```bash
export npm_config_cache=$TMPDIR/npmcache
npm run typecheck            # node + web 两套 tsconfig
npm run build
npm run test:unit            # 15 组单测（不占端口，沙箱内也能跑；M3 新增 7 组，含随机对拍）
npm run test:e2e             # M1 + M2 + M3 三套，需在沙箱外、unset 代理变量（Vision OCR、本地端口、Electron）
npm run test:e2e:m3          # 只跑 M3 套件（约 6 分钟；其中约 40 秒是超时/重试类用例的真实等待）
npm run test:perf            # 500 份卷子 × 40 题的性能测试（约 1.5 分钟，建议机器空闲时跑）
EWB_E2E_ONLY=phaseHot,phaseRealtime npm run test:e2e:m3   # 调试用：只跑指定阶段（正式验证不设）
```

### 3.3 口径（对应设计方案 §4）

| 口径 | 状态 | 验证方式 |
|---|---|---|
| 出现率 = 含该知识点的试卷数 ÷ 筛选内试卷数 | ✅ | 单测手算（甲一x 3/4=75%；次知识点出现也算：甲一y 2/4）；变异测试：把按卷子去重改成按题数 → 单测失败。**E2E 也覆盖了主/次知识点**（返工新增，见下一行）：购物在 C4 里只作为次知识点出现，出现率 1/6 → 3/5（+43.3），手算 |
| 分值占比 = 该知识点题目分值 ÷ 总分 | ✅ | 单测手算：总分 33（分值为空的 P1Q3 不进总分）；甲一x 8/33、甲 16/33。**总分 = 筛选内所有「分值不为空」的题的分值之和**（不是卷面满分，见 §6-2） |
| 向上汇总（子树内任一题 → 这份卷子出现；题数不重复） | ✅ | 单测：P3Q2 同时在甲一x（主）与甲一y（次）→ 甲一只算 1 份、1 道题、4 分；E2E：treemap 一级节点的值 = 逐条循环重算（阅读理解 35、时态 18 等手算） |
| 主/次知识点：都计出现率；分值只按主知识点计 | ✅ | 单测：甲一y 有出现率 50%、2 道题、分值只有主知识点那道的 3 分；细目表次知识点那一行「有题数、分值为 0」；变异测试：分值把次知识点也算 → 单测失败。**E2E（返工新增，夹具里有 3 道带次知识点的题）**：①C4 第 4 题把购物标成次知识点 → 购物出现率 3/5、P2 升降表里是 `3/5 \| +43.3`，但购物的分值占比不含这 3 分；②C1 第 4 题把一般过去时标成次知识点 → 一般过去时「8 题」（7 道主 + 1 道次）、分值仍是 7 题×2 = 14，重难点得分 = 7/11 × 14/97 × (1+2/8)；③A1 第 4 题的次知识点与第 2 题的主知识点是同一个节点（同卷两道题落在同一节点，出现份数不变：名词复数仍是 7/11，手算；题数没有单独断言）；④细目表/CSV：时态 × 阅读选择 = 1 题 / 分值 0 /「仅次知识点」。口径说明弹窗里写明 |
| 分值缺失：不进分值统计，显示「分值覆盖 x/y 题」 | ✅ | 单测：乙一 3 题、其中 1 题无分值 → 分值 6、`scoredPrim=1`；E2E：总览「分值覆盖 56/58 题」、分布「42/44 题」、细目表 CSV 里分值缺失的格子留空（不写 0） |
| 难度、易错一律标「估计」 | ✅ | E2E：难度分布、重难点表头、典型题卡片、抽屉卡片都带「估计」标记（`est-tag` ≥ 2 个；易错原因文案「（估计）」）。⚠️ 没有逐个界面元素穷举断言，是抽查 |
| 口径说明写进界面 | ✅ | 看板顶部与总览都有「口径说明」按钮，E2E 断言弹窗里有：出现率分母、分值占比分母与「分值只按主知识点计」、分值缺失、向上汇总、20 个百分点（含恰好 20）、5 份、综合得分公式、「估计」、默认只统计已确认、重复导入只算一份、按学期对齐、「不是考情结论」。全文见 §4 |

## 4. 口径说明（与界面「口径说明」弹窗一致）

**哪些试卷计入统计**
- 默认只统计状态为「已完成」（老师已审核并确认整份）的试卷。待审核的试卷 AI 标注还没人核对，默认不计入。
- 筛选栏「含待审核」打开后待审核的也计入，界面出现黄色提示条；这些数字会随审核修改变化。失败、处理中的永远不计入。
- **重复导入**：同一个文件导入了多份时，**只算一份**——在当前状态与筛选下可见的几份里先选已确认的、同一状态里再选最早导入的作代表。原件待审核而副本已确认时副本顶上；原件被删了副本也顶上，一份卷子不会因为「是副本」而消失。想让每份都算（会重复计数、抬高出现率）打开「包含重复导入」。有被合并的卷子时，每个页面顶部提示几份。
- 总览、分布、同比、重难点页面顶部都有「范围说明」：几份待审核没计入、几份重复被合并、几份没填学年。

**核心指标**
- **出现率** = 含该知识点的试卷数 ÷ 当前筛选内的试卷数。主指标，不拿原始题数跨年比较。
- **分值占比** = 该知识点题目分值合计 ÷ 总分；总分 = 当前筛选内所有「分值不为空」的题的分值之和。
- **分值缺失**：分值为空的题不进分值统计（出现率、题数不受影响），同时显示「分值覆盖 x/y 题」。
- **向上汇总**：父节点按整棵子树汇总。一份卷子里只要有任意一道题落在子树内就算「出现」，同一份卷子不重复计数；题数同理，一道题只算一次。
- **主/次知识点**：一道题可标 1 个主知识点和最多 3 个次知识点。主、次都计入出现率和题数；**分值只按主知识点计**，避免一道题的分数被重复计算。所以一个知识点只作为次知识点出现时，有出现率、有题数，分值为 0。
- **难度、易错**是 AI 或老师的估计，没有学生成绩，界面一律标「估计」。

**双向细目表**：行 = 知识点（一级或二级，向上汇总），列 = 题型，格子 = 题数 / 分值。标在一级节点上的题，在二级视图里单独成一行「该一级节点本身」。一道题标了多个知识点时在多行各计一次题数、分值只在主知识点所在行计；表尾「全部题目合计」才是真实的题数与分值（含没标知识点的题）。

**同比**：目标学年 vs 基线（默认之前全部学年，或只选某一学年），按所选层级的知识点比较。新增 = 目标出现率 > 0 且基线为 0；消失 = 反过来；上升/下降 = 两边都出现且出现率变化**不小于 20 个百分点**（恰好 20 算）。任一侧不足 5 份显示「样本有限」。**默认按学期对齐**：基线只取目标学年里出现过的学期（当前学年往往只过了一半），页面并排显示两侧学期构成；关掉后基线含全部学期，只在缺少的那个学期里才考的知识点会被报成「新增」「消失」，并有提示。没填学年的试卷不参与同比；筛选栏里的学年在同比页签不生效。教材版本分布并排列出。

**重难点**：综合得分 = 出现率 × 分值占比 × (1 + 1.0 × 易错率)。整个范围都没有分值时，分值占比改用「主知识点题数 ÷ 总题数」并在页面注明。这是启发式排序，不是考情结论；只作为次知识点出现的知识点得分为 0；主知识点标在更高一级节点上的题不属于任何一行，页面单独写出数量与分值。

**结论（如实）**：
- 返工后新增的去重（同一文件只算一份）和学期对齐没有拖慢统计：所有统计接口的中位数都 < 300 ms（最慢的是总览与热点，Electron 里约 215–270 ms；`stats.overview` 的首次调用 299.3 ms，贴着 300 的线）。

- 本次测量时机器 load average 约 3，用户的 `npm run dev` 实例也开着；机器更忙时见过 400 ms 以上的毛刺。

### 性能上做过的事（以及一次真实的退化）
- 第一版性能测试直接**跑不完**：500 份卷子时总览页单个查询 23 秒、「按知识点取题」一次 1.4 秒。原因是没有统计信息时 SQLite 选了「先扫所有卷子、再对每份卷子扫一遍标注表」的连接顺序。修法：所有按范围统计的查询都写成固定的嵌套顺序（`papers → questions → question_kps → closure`，用 `CROSS JOIN` 固定；按知识点取题则反过来从闭包出发），范围条件直接写在 `papers` 上；测试库降到 100 份时看不出来，500 份才暴露。
- 同比、重难点、Top 10 只要某一层级的节点：汇总时直接跳过别的层级（行数少一半以上）。界面上的同比四栏不取样本题（样本题只有 P2 和抽屉用）。重难点的易错原因一次查询取出，不再逐节点各查一次。
- **读缓存状态不再每次重算**（审核 P1-4）：见 §3.7、§12。
- 试过用窗口函数一次取所有节点的样本题，反而更慢（要给 2.7 万行排序），已还原。
- **返工时又踩了一次**：「同一文件只算一份」第一版写成相关子查询（`NOT EXISTS`），按连接后的每一行各算一次，`hot` 要 1.8 秒；改成不相关的 `IN` 子查询（只算一次）后回到原量级（§7-5）。

## 6. 设计决定与「需要确认」（设计方案没说清、我选了一个做法）

1. **重复导入的试卷是否计入**（初版我默认计入，审核判为口径错误；现按协调会话的决定）：同一个文件（`file_hash` 相同）默认只算一份，取「当前状态与筛选下可见的几份里，先取已确认的、同一状态里再取最早导入的」（复审后改，见 §13）；开关改成「包含重复导入（会重复计数）」，默认关。M1 的导入确认框文案相应改成「统计时同一个文件只算一份」。
2. **分值占比的分母**：用「筛选内所有分值不为空的题的分值之和」，不用卷面满分（`papers.total_score` 可能是 AI 猜的，且与题目分值之和常对不上）。好处是分子分母口径一致、各知识点占比之和 ≤ 100%。
3. **同比的知识点层级**：设计方案没说用哪一层。我加了一/二/三级切换，**默认二级**（三级在小样本下太零碎、一级太粗）；总览 Top 10 与重难点默认也是二级。
4. **P2 是「整个同比范围一次分析」，不是「每个知识点各调一次模型」**：P2 提示词的输出结构是五个章节（总体变化 / 新增 / 消失下降 / 高频易错 / 建议），天然是整体分析。因此缓存按「同比范围」存一份；点知识点打开抽屉时，抽屉里显示这份分析中**该知识点自己的小节**（`### 代码｜名称`），没有单独小节的（消失、下降、新增超过 8 个时的后面几个）给出说明，并可「查看完整分析」或直接在抽屉里触发生成（流式显示整篇）。完整分析也放在同比页签底部。
5. **筛选栏只在「总览」和「分析看板」两个页面显示**（审核页要给原卷让位，设置/试卷库有自己的筛选）。侧栏新增「总览」入口，**启动后仍先进试卷库**（M1/M2 的 E2E 与用户习惯都依赖这一点）。
6. **没有学年的试卷**：参与总览与分布，不参与同比，并提示数量。
7. **treemap 的面积**：只用可分拆的口径（分值 / 题数，都按主知识点），颜色才用出现率——出现率不能相加，不适合当面积。
8. **综合得分的权重 1.0**：设计方案只说「出现率 × 分值占比 × 易错」。直接三项连乘会让「没有易错题」的知识点得分为 0，所以用 (1 + 易错率) 把易错当加成；权重 1.0 是我定的，写在口径说明里，改常量 `HOT_FORMULA.errorWeight` 即可。
9. **P2 调用参数**：temperature 0.3（提示词文件的建议）、`max_tokens` 用设置里的「输出上限」、超时用设置里的「超时秒数」（流式时指两段数据之间的空闲）、最多重试 2 次。被长度截断时提示去设置里调大输出上限。重新生成前有「会产生 token 费用」的确认。
10. **每个同比范围只存最新一份**（重新生成覆盖），没有历史版本。
11. **CSV**：每个题型三列（题数、分值、分值覆盖）+ 合计列 + 表尾「全部题目合计」+ 表后附口径说明；有题但主知识点题都没分值时，分值留空而不是 0。
12. **图表自绘**（§3.4）。
13. **同比默认按学期对齐**（协调会话的决定）；目标学年的学期集合 = 目标侧计入统计的试卷里出现过的学期（含「未填」）。
14. **两个「计入范围」开关不记忆**：「含待审核」「包含重复导入」每次启动回到关闭（年级等维度筛选照常记住）。
15. **缓存状态的核对方式**：数据修订号由触发器维护（v7），不靠各处记得去通知；修订号变了才重新核对。代价：任何一张相关表的任何写入（包括提取阶段 `papers` 的进度字段）都会让修订号涨，所以数据一变，下一次读状态会重新核对一次（≈ 一次完整的 P2 输入构造，见 §5）。

## 7. 测试发现并已修掉的真问题（不是写测试时顺手改的）

1. **截图裁切整体错位约一行**：`CropImage` 外框用了 `border: 1px`，而绝对定位子元素的百分比是按「内边距盒」折算的——1px 边框就让 y 方向偏了 0.019（约 31 像素）。E2E 的「容器相对整页图的位置 = bbox」断言第一次跑就抓到（`geo y = 0.2171` 对 `bbox y = 0.2358`），改用 `box-shadow` 画外框后吻合。
2. **取消/失败时丢掉已收到的内容**：`chat()` 每次失败都会回调 `onAttempt`，我在那里把累积文字清空（为了重试从头来），导致最终失败/取消时 `partial` 是空的。改成清空前先存一份。
3. **流式事件与调用返回值的竞态**：`ai:chunk` 事件和 `invoke` 的返回值走两条通道，谁先到不确定。返回值先到时，界面先收尾（没有 `partial`）并删掉请求号，随后到的 `error` 事件被当成陌生请求丢弃。E2E 里这个失败是**偶发的**（同样的用例有时过有时不过）。改成两条通道都能收尾、收尾幂等，返回值里也带 `partial`。
4. **查询计划退化**（§5）。
5. **（审核返工时测出）去重写成相关子查询，整个看板慢 2–10 倍**：第一版「同一文件只算一份」是 `NOT EXISTS (… 同 hash 且更早 …)`，SQLite 按连接后的每一行（题 × 标注）各算一次，500 份卷子时 `hot` 要 1.8 秒、`overview` 0.8 秒。性能测试一跑就看出来；改成「不相关的 `IN` 子查询 + 窗口函数取每组第一份」（只算一次），回到原来的量级。
6. 测试夹具自己的手算错误：阅读理解 33 应为 35（漏了判断正误）、单选 14 应为 18——是我手算错了，应用没错；已改写期望并在注释里写出推导。

## 8. 已知缺口 / 未验证（如实）

- **真实大模型从未调用**：P2 的输出质量、模型是否遵守「不自己算数 / 只引用给定 token / 小标题格式」、流式在真实服务商上的表现（分段大小、`stream_options` 兼容性、断流行为）、真实的 token 用量，全部未知。引用校验与小标题校验是兜底，不是质量保证。
- **仅在 macOS 上验证**，Windows 上没有跑过（M5 做 Windows CI 冒烟时一并验证；本里程碑没有新增原生依赖，交叉编译不受影响）。E2E 里的截图像素核对依赖 macOS Vision OCR（与 M2 相同）。
- **性能**：P2 缓存状态在数据修订号没变时是毫秒级；**数据改动后的第一次读**要重新核对（构造一遍 P2 输入），约 300–350 ms，略超 300 ms 目标（见 §5）；其余接口中位数都 < 300 ms。数据量再大一倍（1000 份卷子）会线性变慢，没有测。
- **图表**：自绘，没有悬浮提示与动画（§3.4）。
- **口径上「没有逐个界面元素穷举」**：「估计」标记是抽查（§3.3）；重难点「没有分值」的退路只有单测（§3.8）。
- **同比只比出现率**，没有按教材版本分别比（两侧教材分布并排列出，由 AI 在分析里区分「教材调整」与「命题取舍」——这一步依赖真实模型）。
- **「重复点击生成」没有单独 E2E**（§3.7）。
- **同比与 Top 10 视图里「标在更高层级节点上的题」不提示**（审核 P2-2）：只有重难点页写出数量与分值；这两处要提示需要再算一遍高层级的主知识点，没做。
- **没做的审核 P2 项**：`ai_analyses` 只增不清（每个范围一行，量很小）；P2 输入的三张变化表没有行数上限（三级知识点 + 很大范围时提示词会很长）；Markdown 渲染没有表格/代码围栏（P2 提示词不用表格，M4 做 P3 时要补）；模型把引用包进 `**…**` 时粗体会断开显示字面 `**`（只影响观感）；单项排序切换（按出现率 / 分值占比 / 易错率）没做。

## 9. 提示词里发现的问题（未改 docs/prompts，仅记录）

1. `HOT` 表的「出现份数/总份数」没有定义分母。我按「跨年高频考点」的字面含义用**目标 + 基线合起来的试卷数**（如 `7/11`），而 `ADDED` / `REMOVED` / `CHANGED` 的分母是单侧试卷数。同一份输入里两种分母并存，模型可能混淆；建议在提示词里写明 HOT 的分母含义，或在表头列里直接写出。
2. `ADDED` 的「分值占比」没有说明分母；分值缺失较多时这个比例偏低。建议提示词增加一个「分值覆盖」占位符（我这边已有数据，加占位符即可），让模型在覆盖率低时不要解读分值占比。
3. 样本提示由程序判定（§七.5）。我把「两侧混入了不同年级/考试类型」也并入了 `SAMPLE_WARNING`，此时文案是「两侧混入了…，对比时请注意口径不一致。」而 system 里写的是「转述该提示，并说明结论仅供参考」——两者对得上，但 system 对「口径不一致」没有专门的写法，模型怎么转述不可预期。
4. 样本题 token 里的试卷标题、题号可能含 `[ ] · |` 或重名/重号（听力一和笔试一各有第 1 题）。程序侧已做清洗与消歧（同名加「（2）」、同号加大题序号），提示词不用改，但 §七.5 的「token 由程序生成」值得补一句「必须唯一」。
5. `FILTER_DESC` 现在带上学期范围（「目标学年 上学期；基线已按学期对齐，只取 上学期」）。提示词没提这一项，但模型会读到；建议在提示词「数据与事实的铁律」里补一句：「学期范围里写的是比较的口径，只在这个口径内下结论」。
6. system 要求「新增超过 8 个时展开前 8 个」，按「目标年出现份数从多到少」——程序给的 `ADDED` 表已按这个顺序排好。
