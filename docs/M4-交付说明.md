## 1. 怎么跑

```bash
export npm_config_cache=$TMPDIR/npmcache
npm run typecheck            # node + web 两套 tsconfig
npm run build
npm run test:unit            # 23 组单测（不占端口，沙箱内也能跑；M4 新增 8 组）
npm run test:e2e             # M1 + M2 + M3 + M4 四套，需在沙箱外、unset 代理变量（Vision OCR、本地端口、Electron）
npm run test:e2e:m4          # 只跑 M4 套件（约 6–8 分钟）
EWB_E2E_ONLY=phaseReport,phaseExport npm run test:e2e:m4   # 调试用：只跑指定阶段（后面的阶段依赖前面的数据；正式验证不设）
```

两个测试专用的开关（都只在环境变量存在时才生效，正常使用不会设）：`EWB_USER_DATA_DIR`（M1 就有）和 **`EWB_TEST_FAULT`**（M4 新增：`after-db` / `after-swap` 让导入在「写完库」「改完目录」之后抛错，用来验证回滚；`cleanup-fail` 让覆盖导入在 **COMMIT 之后** 的清理步骤抛错，用来验证提交之后的失败不会回滚；`move-after-db` 让数据目录迁移在复制完数据库后抛错）。

```
db.sqlite       VACUUM INTO 快照，清理后再 VACUUM INTO 一次（settings 只留白名单、示例卷删除、核对结论清空）
files/<uuid>/original.<pdf|jpg|jpeg|png|heic|docx>
files/<uuid>/page-<n>.png
files/<uuid>/media/<n>.<png|jpg|gif>
```

文件本身已经是压缩格式，打包时 `compress: false`（只压数据库）；用 yazl 流式写，不把整个包读进内存。导入解包同样是流式（yauzl），一次只在内存里有一个 chunk。

## 6. 已定的决定与实现取舍

### 6.0 协调会话已定（首轮审核后，原「需要确认」里的项）

1. **内置知识点节点**：允许改名、**停用 / 重新启用**（可逆），**不许移动、不许被合并掉、不许删除**——维持现状（可作合并的目标）。
2. **合并导入时同一个文件、不同 id**：保留两条并标 `duplicate_of`，统计只算一份——维持现状。
3. **覆盖导入的备份**：保留最新 2 份、**手工恢复**（没有一键恢复）——维持；**设置页的备份列表现在显示备份所在的完整路径**，方便老师自己找（E2E 断言路径文字）。
4. **数据目录更改**：需要重启才生效，不做热切换——维持（拦截的状态放在主进程，见 §3.6）。
5. **数据包大小上限**（10 万条、总 8 GiB、单文件 200 MiB、数据库 2 GiB）——维持。

另外，审核 P2-3 建议「覆盖导入保留本机的自定义提示词、不随包覆盖」，已采纳并写进 §3.5：**设置一律不覆盖——本机已有的保留，只补本机没有的（且逐键校验）**；导入前的备份里也没有设置的专门备份，所以本机的提示词 / AI 配置不被动是更安全的做法。

### 6.1 其余实现取舍（设计方案没说清、我选了一个做法）

1. **停用一个节点连同它的子树**：避免父节点停用了、子节点还挂在选择器里。重新启用只启用被点的节点（子节点要各自启用）。
2. **示例数据怎么「不混进统计」**：默认统计只看真实数据，示例数据要在筛选栏切到「示例数据」才看得到（没有用「过滤」的做法，因为任务书允许做不到才退而求其次，这里做到了）。`ui_stats_filter` 会记住当前停在示例数据，重启后若示例数据已被清除则自动回到真实数据。
3. **首次启动卡片什么时候出现**：打开应用时库里已经有真实试卷（升级上来的老用户）就不出现、直接记为已引导；全新库出现，直到点「不再显示」。教材版本只作 AI 没读出教材时的默认值，不会覆盖 AI 读到的。
4. **每次生成报告新增一条历史**（不覆盖），最多 100 条；「已过期」由实际发给模型的文本判断，换了模型只提示不算过期（与 P2 一致）。
5. **报告里的知识点分布表**：一级全列，二级按出现份数从多到少最多 30 个，多出来的在表尾写「另有 N 个已略」（输入太长会让模型啰嗦、也费 token）；易错点表最多 10 行；年度变化摘要每类最多 8 项。
6. **报告里的「题数」与「分值占比」**：沿用 M3 口径——题数含次知识点、分值只按主知识点。提示词没有对这两列的口径做说明，见 §9。
7. **导出的 Markdown 里没有定位框的引用**：用整页缩小到 900 宽（与界面「没有定位框就显示整页缩略图」一致）。
8. **导出 / 覆盖 / 迁移前要求没有后台任务**：提取 / 解析队列有任务、AI 在生成时先提示等待（`busyReason`）；这是我加的，避免页面图写到一半被打包或被换掉。

## 7. 测试发现并已修掉的真问题（不是写测试时顺手改的）

1. **暂存的弹窗内容在关闭后还留着**（antd Modal 关闭后不卸载子节点）：重新打开「更改数据目录」时先闪出上一次选的目录和错误信息；E2E 里连续选几个目录时读到的永远是上一个的结果。三个弹窗加 `destroyOnHidden`。
2. **示例数据加载后看板立刻被切回真实数据**：筛选栏的「示例数据已被清除就自动切回」读到了缓存里旧的「没有示例数据」。E2E（首次启动那一步）第一次就抓到；改成重新取数期间不判断，并在加载 / 清除后先更新缓存再改筛选。
3. **点一下已选中的知识点节点会取消选中**（antd Tree 默认行为），操作按钮随之消失；改成不取消。
4. **进度文字残留**：导入完成后「正在安全解包… 2/3」还显示在数据存储卡片里（进度事件晚于返回值到达）；改成只在操作进行中显示，并给事件限频。
5. **变异测试暴露的 3 个测试缺口**（不是应用的 bug，但原来的测试会放过它们）：只有 `integrity_check` 才发现得了的损坏；旧版本数据包里的触发器要在迁移**之前**删（原先的旧库样本版本太新，迁移不会触发它）；库里留着上一次成功导入的 `import_marker` 时，崩溃恢复不能把这一次误判为已提交。已补用例。

## 8. 变异测试

对数据包、知识点编辑、P3、示例数据、数据目录的 42 处关键逻辑做了「改坏一处，看对应的单测会不会失败」（脚本一次改一处、跑单测、还原）。第一轮 12 处没被抓到，逐个分析：

- **真的测试缺口，已补用例（3 处）**：只有 `integrity_check` 才发现得了的损坏；旧版本数据包里的触发器要在迁移**之前**删（原先的旧库样本版本太新，迁移根本不会触发它）；库里留着上一次成功导入的 `import_marker` 时，崩溃恢复不能把这一次误判为已提交。
- **互为冗余的防线（6 处，3 对）**：头部声明大小检查 vs 流式实际字节计数；名字里的 `..` / 绝对路径 / 控制字符检查 vs 白名单正则；`secure_delete` vs 二次 `VACUUM INTO`。单独去掉任一个测试都不失败。第二轮做了组合变异：头部检查 + 流式计数**同时**去掉 → 被抓到；`secure_delete` + 二次 `VACUUM INTO` 同时去掉 → 被抓到；名字那一组（三项检查同时去掉）**仍然不失败**——白名单正则本身已经把这些名字挡在外面，所以那三项是纯冗余，保留是为了防御纵深。
- **等价变异（3 处，改了行为不变）**：覆盖模式把「待导入集合」按合并方式算（覆盖前已清空，结果相同）、清除示例数据时报告删除条件里多出来的分支、`copyDirSync` 的符号链接分支（`Dirent` 对符号链接本来就既不是文件也不是目录）。

其余 30 处一次就被抓到（流式总量上限、条目数上限、符号链接、版本过新、页面图路径校验、合并的 UUID 去重、题目 id 撞车、ROLLBACK、`revertSwap`、目录回移、知识点代码改号、备份修剪、导出时的白名单设置和示例卷删除、内置节点保护、迁移题目关联、事务回滚、样本提示兜底、分值覆盖警告、围栏解析、HTML 转义、`is_sample` 隔离、清除示例文件、数据目录的「在里面 / 上级」检查……）。E2E 层没有做系统性的变异检查。

## 9. 提示词里发现的问题（未改 `docs/prompts`，仅记录）

1. `KP_DIST` 的「题数」含次知识点，「分值占比」只按主知识点（M3 口径），同一行里两列口径不同；提示词没有说明，模型可能拿「题数 × 平均分」去解释分值占比。建议在提示词里写明，或表头里直接标「题数（含次知识点）」。
2. 「分值覆盖」没有占位符。分值缺失较多时分值占比偏低；我把它并进了 `SAMPLE_WARNING`（覆盖 <90% 时警示），模型会当作样本提示转述。建议提示词加一个「分值覆盖」占位符。
3. `YEAR_DIFF` 的格式提示词没有规定（只说「年度变化摘要」）。我写成固定的多行：口径行（目标 / 基线份数、学期范围）+「新增 / 消失 / 明显上升 / 明显下降」四行，每行最多 8 项并写明「另有 N 项未列出」。建议提示词把这个格式写进占位符表。
4. system 要求「除样本概览外每章固定三行：结论 / 依据 / 建议」，但「教学建议」一章要求「3–5 条，每条末尾括号注明对应哪一节」——两条规定对最后一章冲突；我的 mock 按后者写。
5. system 要求「样本提示为『无』时不要写任何样本提示」，同时程序侧约定要保证样本提示一定出现：我的兜底只在提示非「无」且模型没转述时补，不会在「无」时多写。
6. `FILTER_DESC` 在 P3 里去掉了「按 N 级知识点统计」（P3 的知识点表同时有一、二级），并在示例数据范围下写明「示例数据（合成的演示卷，不是真实考情）」——免得报告被当成真实考情；提示词没有提这一点，但标题 `# {筛选条件} 考情分析报告` 会带着它。
7. 「每个知识点最多引 2 道」：易错点表里每行给的样本题就是最多 2 道（易错的优先、难度高的在前），模型无需自己挑。

## 10. 已知缺口 / 未验证（如实）

- **真实大模型从未调用**：P3 的输出质量、是否遵守「不自己算数 / 只引给定 token / 每章三行」、流式在真实服务商上的表现，全部未知（§3.1）。
- **仅在 macOS 上验证**，Windows 上没有跑过：PDF 中文字体回退链（§3.2）、`fs.rename` 目录在 Windows 上被占用时的行为（覆盖导入遇到占用会走回滚并报错，没有实测）、Windows 路径大小写比较、示例页面渲染用的字体。E2E 里的截图像素核对（OCR）依赖 macOS Vision。
- **崩溃恢复没有真的杀进程测**，靠单测里模拟「journal 已写、目录已换、事务未提交」等四个时间点（§3.5）；E2E 里用「预先放好 journal 再启动」验证启动提示。
- **journal 的理论篡改面（复审 P2-5，已收紧、剩余风险记在这里）**：journal 现在只认 `files` 和 `backups/pre-import-…/files` 两个位置，别的一律不认；但能写这台电脑数据目录的人仍然可以手写一份「合规」的 journal，让下次启动把 `files/` 和某个备份目录互换——结果仍在数据目录里面、可逆，不会碰到数据目录之外的东西。能写数据目录的人本来就能直接改库，所以不再加签名。
- 「立即重启」按钮、配置目录不可用时的启动对话框：没有自动化（§3.6），手工验证方法已写。
- **迁移数据目录会带走 `backups/`（复审 P2-8）**：备份最多 2 份，每份是当时的整库加整个 `files/`，所以迁移时占用的空间和时间可能接近翻倍；界面说明里写了会复制备份，但没有做「不带备份」的选项。旧目录里的备份原样保留（旧目录整体不动）。
- 旧版本数据包的导入只有单测（用真实迁移造的 v3 / v5 库），E2E 里没有；数据包 E2E 用的是当前版本（v9）的包。
- 报告列表在数据变化后要逐条重新核对（同一筛选只算一次）：几份没问题；上百份且每份是不同筛选时，数据变动后的第一次打开报告页会慢（每条约一次完整的 P3 输入构造，500 份卷子的库里约 0.5 秒量级）。没有为 P3 专门做性能测试。
- 数据包没有加密、没有签名：「不可信输入」的防护针对的是恶意 / 损坏的包，不是防篡改。导出的包里有老师的全部试卷原件，请像对待试卷一样保管。
- 更改数据目录的「需要重启」拦截现在由主进程持有并拒绝写入类请求（§3.6），不再只是界面层；但页面之外**已经在跑**的后台任务不会被中断（所以迁移前要求没有后台任务）；没有 `kill -9` 在迁移中途的测试（靠 `.migrating` 标记的单测）。
- **导出写文件失败的 E2E 是注入的**：用 `process.getBuiltinModule('fs')` 在主进程里把 `createReadStream` 对 `page-1.png` 换成会报 `EBUSY` 的流；单测用同样的办法。真实的杀毒软件 / 同步盘占用文件在 Windows 上没有实测。
- 夹具里的样本题截图用同一张页面图（M3 遗留）；示例数据的页面图是渲染出来的，语义对得上。
- 首次启动卡片里「教材版本」的默认值补充没有单独断言（§3.8）。
- 审核页等 M2 的已知缺口不变（见 M2 交付说明 §6），M3 的已知缺口除 §3.11 里收掉的以外不变。
- **主线程长时间同步工作（审核 P2-7，未改）**：`node:sqlite` 是同步的，`integrity_check` / `foreign_key_check` / 整个 `apply*` 都在主进程里，数据库到 2 GiB 上限时窗口会无响应一阵；`pickPack` 的解包没有接取消信号（无法中途取消）；解包前不检查磁盘剩余空间（上限 8 GiB 会写进数据目录所在盘）。改成 worker 线程成本高，留给 M5 评估；常规大小（几十 MB 的库、几百份卷子）导入是秒级。
- **导出期间的拦截是粗粒度的**：只拦「会改写试卷文件」的请求（§3.3），不拦读取和审核编辑；快照在导出开始时一次取完，之后的审核修改不会进这个包（这是预期）。

#### P1-A 导出读文件失败：主进程未捕获异常 + 导出永不结束 + 锁不释放

| 项 | 内容 |
|---|---|
| 原因 | yazl 读文件失败时 `error` 发在 `ZipFile` 上，不在 `zip.outputStream` 上；`buildPack` 只听了后者和写出流。没有监听器的 `error` 事件在 Node 里就是未捕获异常，同时 Promise 永远不结束，`withOp` 的 `opActive` 和 `exporting` 都不会释放，之后的导入 / 改目录 / 示例数据全被挡住直到重启，`.part` 也留在原处 |
| 修法 | `exporter.ts`：新增 `zip.on('error', fail)`；`fail` 只 reject 一次、先 `unpipe`、再 `out.destroy()` 销毁写出流（否则句柄不释放，Windows 上删不掉 `.part`），`close` 事件在失败后不再 resolve。失败走原有的 catch：删 `.part`、删快照、`ENOSPC` / `EACCES` / `EPERM` / `EBUSY` 映射成中文，其它写「导出失败：…」；`data.ts` 的 `finally` 释放 `setExporting` 和 `withOp`。界面在设置页的数据包卡片里显示中文原因，按钮恢复可点 |
| 单测 | `pack-db`：把 `fs.createReadStream` 对 `page-1.png` 换成会报 `EBUSY` / `EIO` 的流，断言 `buildPack` rejects 一个 `PackError('io')`、消息是中文、**没有 `uncaughtException`**、`.part` 和数据包文件和快照都不在；然后同一个库再导出一次成功。带 4 秒超时，所以「Promise 永不结束」会表现为断言失败而不是挂住。**变异：删掉 `zip.on('error')` → 测试以「buildPack 没有结束（Promise 永不 settle）」失败** |
| E2E | `m4-phases-data`「数据包 导出失败」两条：主进程里把 `createReadStream` 对 `page-1.png` 换成 `EBUSY` 流 → 点「导出数据包」→ 界面出现中文原因，主进程 `uncaughtException` 计数为 0，没有 `.part` 也没有半截数据包，按钮可点；还原后同一个会话里再导出成功、选这个包 `pickPack` 走到摘要、API 再导出也成功（导出锁和操作锁都释放了） |
