## 一、问题清单

### P0（必须修）

**P0-1　「排除重复导入」会让唯一的一份试卷整份消失（口径错误，已复现）**
- 位置：`src/main/stats/filter.ts:50`（`if (f.excludeDuplicates) parts.push('p.duplicate_of IS NULL')`）；`src/main/pipeline/queue.ts:129` 说明 `duplicate_of` 只标在**后导入的副本**上，原件为 NULL。
- 问题：开关的实现是「凡是副本一律排除」，不看原件有没有被计入。以下两种情况副本是**唯一的**计入对象，打开开关后却被排除，试卷数少 1：
  1. 原件还在 `reviewing`（或其他不计入的状态），副本已 `done`。
  2. 老师导入了两次后把旧的那份删掉了（`duplicate_of` 指向一个已不存在的 id，没有外键）。第 2 种是「导入重复了就删一份」这种最自然的清理动作，而会去打开这个开关的，恰恰是知道自己导入过重复的老师。
- 复现（`$TMPDIR/rv/dup.mjs`）：造原件 `reviewing` + 副本 `done` → `distribution(db,{excludeDuplicates:true}).papers = 0`（应为 1）；造一份 `duplicate_of='已删除的id'` 的 done 副本 → 同样为 0（应为 1）。
- 影响：试卷数分母少 1，所有出现率、同比的 5 份门槛、总览数字都变；界面只会说「N 份是重复导入的」，看不出这份其实没有任何替身。
- 修法：排除副本的条件改成「它的原件**也在本次计入范围内**才排除」，例如
  `NOT (p.duplicate_of IS NOT NULL AND EXISTS (SELECT 1 FROM papers o WHERE o.id = p.duplicate_of AND o.status IN (<本次计入的状态>) AND <o 满足同样的筛选>))`；
  或者按 `file_hash` 分组，每组只留一份计入的（优先 done、其次最早导入）。同时补两个单测：原件不计入、原件已删除。

### P1（应修）

**P1-1　重复导入默认算两次，且同比 / 重难点页对此完全不提示**
- 位置：`filter.ts:6-7`（默认计入）、`StatsFilter.tsx:108`、`Parts.tsx:21-28`（`NotCounted` 只被 `DistributionTab`、`Overview` 用，`CompareTab.tsx`、`HotTab.tsx` 没有）。
- 问题：老师在 M1 导入框点「仍然导入」，是在确认「我要导入这个文件」，不等于确认「请在统计里把它算两次」。把同一份卷子算两次会抬高它所含知识点的出现率，又会让同比的某一侧份数偏大，直接影响「新增/上升」的判定。而且「重复」「待审核」的提示只在两个页面出现；老师最常看的同比页和重难点页什么都不说。
- 建议：默认**排除**重复副本（修好 P0-1 之后）；开关改成「包含重复导入的副本」；同比页与重难点页也显示 `NotCounted`（至少显示「含 N 份重复导入」）。如果坚持默认计入，至少要在这两页常驻提示。

**P1-2　同比不识别「学期不齐 / 学年未完」，会把没考到的知识点报成「消失」**
- 位置：`core.ts:484-489`（`mixed` 只看年级与考试类型）。
- 问题：同比的单位是「学年」，但一个学年有上、下两学期。**当前学年通常还没过完**（今天 2026-10，2026-2027 学年只会有上学期的卷子），而基线是完整的上+下学期。我造了这个场景（`scen.mjs` 最后一段）：基线 2024 年上学期 5 份（只考 RD.D）+ 下学期 5 份（只考 G.N），目标 2025 只有上学期 5 份 → 「G.N」被判为**消失**（基线 5/10、目标 0/5），两侧都 ≥5 份、`mixed` 为空，没有任何提示。老师会据此认为「这个知识点不考了」。
- 建议：`mixed` 增加「两侧学期构成不一致」（目标侧与基线侧的 `semester` 集合不同）的提示，文案写明「当前学年还没有下学期的卷子，下学期才教的知识点会显示为消失」；P2 的 `SAMPLE_WARNING` 同步带上。更稳妥的做法是同比页默认带上学期筛选，或在目标学年只覆盖一个学期时自动只取基线的同一学期。

**P1-3　流式「干净 EOF」会把半截分析当完整结果存库**
- 位置：`src/main/ai/client.ts:172-201`（流读到 `done` 就收尾，不要求见到 `finish_reason` 或 `[DONE]`）、`client.ts:224-231`（只检查 `length`）、`stats/analysis.ts:182-213`。
- 问题：交付说明 §3.7 的「中途断流 ✅」测的是 mock 用 `res.socket.destroy()` 硬断（读流抛异常 → 重试）。但网关、代理、部分国产服务商超时时会**正常关闭**连接而不发 `finish_reason`：读流 `done=true`，`finishReason=''`，`content` 是半截。`chat()` 照样返回，P2 把它去引用后 `INSERT OR REPLACE` 进 `ai_analyses`，界面显示「已缓存」。P1 的 JSON 输出半截会因解析失败被发现，Markdown 自由文本不会。
- 建议：流式场景下，读完后若既没有 `finish_reason` 也没收到 `[DONE]`，当作 `network`（数据流中断）重试/报错；P2 另加完整性兜底（例如 system 约定的 `## 五、…` 章节标题不在输出里，就不存库、标「可能被截断」）。补一个 mock 用例：发 N 段后正常 `res.end()`。

**P1-4　读缓存状态要整套重算，325 ms 是设计造成的，而且阻塞主进程**
- 位置：`stats/analysis.ts:48-61`（`prepare`）、`analysis.ts:94-122`（`analysisState`）、`App.tsx:36`（每次 `data:changed` 都失效 `['stats']`）。
- 原因：判断「已缓存还是已过期」需要数据指纹，指纹 = 整份 P2 输入的哈希，所以 `analysisState` 在有缓存时调用 `prepare()`：`compare(..., 样本3)`（两侧 `nodeStats` + 每个变化项一次取样本题）+ `hot(..., 15, 目标∪基线)`（又一轮 `nodeStats` + 一次易错原因查询 + 15 次取典型题），本质是**把统计页上已有的三轮大聚合再来一遍，只为比较一个哈希**。我在 500×40 的内存库上拆开测：`compare` 约 85 ms、`hot` 约 140 ms，合计约 220 ms（交付说明在 Electron 里是 325 ms）；`buildP2Input` 本身 0 ms。没有缓存时只数两个试卷数，所以「常规路径」很快，掩盖了问题。
- 影响：①每次点开同比页、每次 `data:changed` 都会在**主进程同步线程**上多占 200–300 ms（`node:sqlite` 是同步的）；这期间 IPC、流式 `ai:chunk` 的 40 ms 刷新都会被卡住。②试卷再多一倍就线性变慢。③ `FilterBar` 另外还在每次筛选变化时多跑一次完整的 `stats.overview`（见 P2-8）。
- 建议（任选其一，成本由低到高）：①给 `ai_analyses` 存一个轻量的「数据版本」——主进程维护一个单调递增的 `dataVersion`，在 `notifyDataChanged`（`events.ts`）里自增；`analysisState` 先比 `(scopeKey, dataVersion, promptVersion)`，没变就直接返回上次的结果，变了才重算，并把结果记在内存里；②指纹改成对「范围内试卷 id + 各卷最近修改标记 + 提示词版本」的廉价哈希（需要给 papers/questions 加 `updated_at`，属于新迁移）；③把统计放到 worker。不管哪种，都要让「读状态」不再触发完整统计。

**P1-5　缓存键里的「提示词版本」靠人工维护，漏改会让过期结果显示为「已缓存」**
- 位置：`src/main/ai/prompts.ts:20`（`PROMPT_DEFAULT_VERSION = 'v1.1'`）、`prompts.ts:122-130`（`promptVersionFor`）。
- 问题：用户自改提示词时版本里带了哈希（好）；但**内置**提示词变了（程序升级、改 `prompts/p2_yoy.*.txt`）只靠开发者记得把常量从 v1.1 改成 v1.2。`prompts-sync.test` 只比较「资源文件 = docs」，不会逼人升版本。漏改的后果就是：旧分析用的是旧提示词，缓存键一致，界面写「已缓存」，没有任何提示。
- 建议：版本标识里直接放**实际生效的 system+user 模板文本的哈希**（默认值也算），把人工版本号只当显示名；或加一个单测：对三个内置 P2/P1 资源文件做哈希快照，改了文件而没改快照/版本就失败。

**P1-6　同比范围键包含「在同比页不生效的学年筛选」，会无故丢缓存**
- 位置：`CompareTab.tsx:47`（`scope = { filter, ... }`，`filter` 含 `school_year_start`）、`analysis.ts:33` / `p2.ts:143`（`normalizeFilter` 原样保留）、`ipc/stats.ts:20-24`。
- 问题：同比页明确说「筛选栏的学年在这里不生效」（`compare()` 也确实覆盖了它），但传给 P2 的 scope 里仍带着它，`scopeKey` 因此随之变化。老师在筛选栏换了一下学年，同比的四栏一点没变，AI 分析却回到「还没有分析」，要再花一次 token 才能拿回同样的结果；切回去旧的缓存还在，所以是「看不到」而不是「丢了」，但很容易误导。
- 建议：在 `toScope`（`ipc/stats.ts`）和 `CompareTab` 里把 `school_year_start` 从 filter 中剔除再算键与请求；顺带补一个 E2E：同比页改学年筛选，AI 分析状态不变。

### P2（建议）

1. **总览「本学年新增知识点」没有样本量提示**（`core.ts:565`、`Overview.tsx:45-49`）：`compare()` 已经算出了 `limited`/`mixed`，总览却不展示。目标学年只有 1–4 份卷子时，几乎所有知识点都会被列为「新增」。建议带上同比页同样的「样本有限」「学期不齐」提示。
2. **标在一级节点上的题，在二级/三级视图里被静默丢掉**（`core.ts:94-95` 的 `ak.level = ?`，同比/重难点/Top 10/考频都这样）。我实测：一道题标在一级「A」、另一道标在二级「A.1」，重难点二级视图只剩 A.1，那 5 分不出现在任何一行，也没有「N 题标在更高一级节点上，未计入本视图」的说明。细目表有「该一级节点本身」行，这几处没有。建议加一个说明条。
3. **细目表的格子分值有两处会被误读**（`DistributionTab.tsx:142-143`、`csv.ts:20`）：①一个格子里 3 题只有 1 题缺分值时，显示的是另外 2 题的和，没有任何标记（`—` 只在整格都缺时出现）；②只作为次知识点出现的格子显示「2 题 / 0 分」，容易被理解成「这些题 0 分」。我实测：2 题（1 题 2 分、1 题无分值）→ 显示 `2 题 / 2 分`。建议格子显示「2 分（1/2 题有分值）」，次知识点格子写「—（次）」，CSV 在末尾列多加一列「分值覆盖」。
4. **重难点只列前 20 行且不说明**（`core.ts:370 limit=20`、`HotTab.tsx`）。二级知识点约 67 个，老师不知道后面还有。另：只作为次知识点出现的知识点 `priority=0`，会垫底（因为分值占比为 0），建议在口径说明里写明，或对这类知识点单独标注。
5. **综合排序公式的取舍**：`出现率 × 分值占比 × (1 + 易错率)` 的前两项高度相关（出现得多，分值占比自然大），实际是在平方放大「大户」；易错项最多只让得分 ×2，对 AI 估计的易错只是轻微加权，这点是对的。建议保留，但在口径说明里写清「这是启发式排序，不是考情结论」，并考虑给老师一个「按出现率 / 按分值占比 / 按易错率」单项排序的切换。
6. **`CSV` 缺少口径信息**（`csv.ts`）：导出的文件里没有筛选条件、试卷数、是否含待审核、分值覆盖率。文件一旦被转发，数字就脱离了口径。建议加一行说明或文件名带筛选摘要。另外 `fs.writeFileSync` 在 Excel 正占用文件时会抛英文 `EBUSY`（`ipc/stats.ts:47`），建议转成「文件正被其他程序占用，请关闭后重试」；BOM 在源码里是一个不可见字符（`csv.ts:29`），建议写成 `'﻿'`，避免被编辑器/格式化工具吃掉。
7. **`includeReviewing` 随筛选一起持久化**（`StatsFilter.tsx:41-43`）：重启后仍是「含待审核」，用户可能忘了。有黄条提示，所以不算错误，但「安全默认值」是只统计已确认，建议每次启动把两个开关重置（或者在启动时弹一次提示）。
8. **多余的 `stats.overview` 调用**（`StatsFilter.tsx:86`）：`FilterBar` 为了拿「待审核份数」调用完整的 `overview`（含 Top10、同比、最近导入，约 250 ms），而且不受 `ready` 控制，启动时先用空筛选跑一次。建议单独做一个轻量的 `stats.counts` 接口。另外分布/重难点切筛选时 `if (isLoading || !d) return <Spin>` 会让整页闪成转圈，建议用 `placeholderData: keepPreviousData`。
9. **抽屉里的 `item` 是点击时的快照**（`CompareTab.tsx:101`、`KpDrawer.tsx:14`）：抽屉开着时发生 `data:changed`，下面题目卡片会刷新，上面的「基线 x/y → 目标 x/y」不会。建议只存 `code`，每次从最新的 `cmp` 里查。
10. **`senderGone` 监听器只加不删**（`ipc/stats.ts:72`，`sender.once('destroyed')`）：同一窗口里生成 11 次以后 Node 会打印 `MaxListenersExceededWarning`。生成结束后应取消监听。
11. **生成中整页刷新（Cmd/Ctrl+R）会丢结果显示**：主进程会继续生成并存库，但新页面里 `byId` 是空的，`done` 事件被忽略，没有 `data:changed`，所以新页面要等下一次 `staleTime` 过后才看到。建议存库后 `notifyDataChanged('analysis')`（`STATS_SOURCES` 里本来就有这个名字）。
12. **「重试 / 重新生成」在失败、取消状态下不再确认费用**（`AnalysisPanel.tsx:23-27,48,54`，`gen(label)` 的 `danger` 默认 false）：如果之前有缓存，重试成功会覆盖它，而这一步没有「会产生 token 费用、会覆盖旧结果」的确认。
13. **缓存键不含模型**：换了模型后旧分析仍显示「已缓存」（界面会写模型名，所以不算误导，但可以在 stale 原因里加「模型变了」）。
14. **`settings:set` 对新键 `ui_stats_filter` 没有 zod 结构校验**（`ipc/settings.ts:28-34`，只有大小限制）。读回时渲染端 `sanitizeFilter` 做了白名单，所以没有实际风险；但与交付说明「参数一律 zod 校验」的说法不完全一致。建议给该键挂 `StatsFilterSchema.safeParse`。
15. **`filterOptions` 不受「含待审核」影响**（`core.ts:589`）：筛选栏下拉里会出现「只在待审核卷子里有」的教材/地区/学年，选了就是空结果。
16. **Windows 上单测会整批失败的隐患**（`tests/unit/helpers/db.mjs:14`）：正则写死了 `\n\nlet db: any`，Windows 上 `core.autocrlf` 默认会把 `db.ts` 检出成 CRLF，`MIGRATIONS` 就找不到。`.gitattributes` 只管了 prompts。改成 `\r?\n\r?\n`，或给 `src/main/db.ts` 加 `eol=lf`。
17. **其他小项**：Treemap 小格子文字被裁掉后没有 `title`（`Treemap.tsx:24`），看不到名字；细目表第一列不是 sticky，横向滚动后看不见行名；`CropImage` 在 DB 里的页面尺寸与图片自然尺寸宽高比不一致时（例如 EXIF 旋转）会变形，建议图片加载后优先用自然尺寸（`CropImage.tsx:12-13`）；`ai_analyses` 只增不清；P2 输入的三张变化表没有行数上限，三级知识点+大范围时提示词会很长；Markdown 渲染没有表格/代码围栏支持（P2 提示词不用表格，但 P3 会用，M4 要补），模型若用 ```` ``` ```` 包裹全文会原样显示围栏；`sectionFor` 对 `### \`CODE\`｜名称`（代码带反引号）找不到小节，会显示「完整分析里没有单独讨论」，这时 `headingCodes` 的校验会同时给出警告，所以不致命。

## 四、对「重点核查」逐条的判断

### 1. 口径正确性
- **SQL**：`nodeStats` 先按 `(题, 祖先节点)` 分组（`MAX(is_primary)`、`MIN(主知识点的深度)`），再在节点上聚合，这样同一道题（主次都落在同一子树）只算一次、同一份卷子 `COUNT(DISTINCT paper)` 只算一次，分值只从 `prim=1` 的分组累加，逻辑正确。分值为空：`SUM(score)` 本来就忽略 NULL，`scoredPrim` 单独数，总分只含非空分值，覆盖率是「非空题/全部题」。
- **单测期望值**：`stats-core`、`stats-compare-math`、`stats-p2`、`stats-csv` 的期望值都是手算常数（带推导注释），没有用被测函数再算。我逐项复算了 `stats-core` 的 S1 数据集（总分 33、甲一 3 卷/4 题/11 分等），都对。有一句注释笔误（`stats-core.test.mjs:86` 注释写 16+6+10+1=33，断言是 32，断言是对的）。
- **`naive.cjs`**：算法与 SQL 无共享代码，是真独立实现，能抓到「SQL 写错」这一类问题（它也确实在交付说明 §7 里抓到了作者自己手算的 2 处错）。局限：它和夹具读同一份 `SPEC`、同一套解释，所以**抓不到「解释错了」**；且夹具里没有次知识点（见第二节表格），主次逻辑在 E2E 层没被检验。
- **筛选一致性**：`paperScope` 是唯一入口，overview / distribution / matrix / hot / compare / questions / exportMatrix / P2（含 `hot` 的「目标∪基线」范围）全部经过它；同比自行覆盖学年，其余条件一致生效。唯一的例外是 `filterOptions`（P2-15）。

### 2. 编码会话自己定的做法
- **重复导入默认计入 + 开关**：不合理，原因和修法见 P0-1、P1-1。
- **图表 DOM 自绘**：合理。对这一版（treemap、条形、细目表）来说，纯 DOM 便于 E2E 断言每个格子的值和位置、不增依赖，也没发现性能问题（几百个节点）。代价（无悬浮提示）可以接受，但小格子要加 `title`（P2-17）。
- **同比与重难点默认二级**：合理（67 个二级、64 个三级、14 个一级，二级粒度对老师最有意义），层级可切换，并且口径说明里写了。唯一的风险是「标在更高层的题被静默丢弃」（P2-2）。
- **P2 按整个范围分析一次再按知识点切片显示**：合理，也是提示词本身的输出结构（五个章节）决定的；抽屉里显示该知识点自己的小节，没有小节时会明确说明「完整分析里没有单独讨论」，不会让老师误以为是空。需要注意的是它意味着**抽屉里点开一个知识点就可能触发整篇生成的费用**，目前首次生成没有费用提示（重新生成才有，P2-12）。
- **重难点排序公式**：可用，见 P2-4、P2-5。已明确写在界面与口径说明里，并且单测手算了三个知识点的得分。

### 3. P2 AI
- **占位符**：`fillTemplate` 找不到值时抛错，`prepare` 捕获后作为 `promptError`，`generateAnalysis` 见到就直接返回 `bad_prompt`，不会把 `{{…}}` 发出去；`savePrompt` 对 `ADDED/REMOVED/CHANGED/HOT` 设了必需检查。12 个占位符全由 `buildP2Input` 本地算出，模型不参与计数。✓

### 6. 性能

- **筛选持久化**：✓（`ui_stats_filter` + 读回白名单）。注意 P2-7。
- **`data:changed` 刷新**：同一 queryKey 的后台刷新不会闪（react-query 保留旧数据）；会闪的是「切筛选」（P2-8）。我没发现竞态：`finishOk` 先失效查询再清掉进行中的记录，E2E 里有「不闪回『还没有分析』」的断言。
- **抽屉 / 截图坐标**：`CropImage` 的数学我手推了一遍：容器宽 W、`img` 宽 `100/w %`、`left=-x/w×100%`、`top=-y/h×100%`（`top` 的百分比按容器高度折算，而容器高度 = W·h·ph/(w·pw)，推得偏移正好是 `y/h`），正确；`border` 改 `box-shadow` 的修复也是对的。bbox 的 0–1 归一化在 `PageViewer` 高亮同样正确。
- **大量知识点时**：同比四栏有 `maxHeight: 420` 滚动；细目表有 `maxHeight: 520` + sticky 表头；Treemap 小格无名字（P2-17）；重难点最多 20 行。可用。

### 8. 测试可信度
- 没有发现写死为真的断言或无效检查。E2E 里有几个 `.catch(() => {})` 只用在「等弹窗消失」这类清理动作上。`check('页面','控制台没有报错', ...)` 是真断言。

- M1/M2 的 E2E 没有被改弱（见第二节）。

### 9. 跨平台
