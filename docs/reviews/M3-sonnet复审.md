### 2.3 随机对拍（`fuzz.mjs`）

300 个随机库（8–25 份卷，hash 池约 60% 重合，状态 done / reviewing / failed / imported，学期 上 / 下 / 空，年级 4 / 5，2023–2025 学年，次知识点 30%、分值缺失 20%），每库 7 种筛选组合（含两个开关的组合、年级、学期、年级 + 学年）。用**不共享任何 SQL 的逐卷逐题循环**计算期望，对拍：

- 总览 / 分布 / 细目表 / 重难点的卷数全相等；分布的题数相等；
- 每个知识点节点的「出现卷数 / 题数 / 主知识点分值」全相等，节点个数相等；
- `scopeNotes` 的待审核总数、合并份数相等；
- 同比（对齐开 / 关各一次）的目标 / 基线卷数、`dropped`、新增 / 消失 / 上升 / 下降的二级知识点集合相等（整数判定 20 个百分点）。

**2100 组判断，0 处不一致。** 为确认脚本不是空转：把朴素实现里的去重条件反过来，立刻出现 21046 处不一致。

结论：去重子查询在各统计接口之间一致；总览、分布、同比（目标侧）、重难点的卷数在任何筛选与开关组合下都对得上。**唯一例外是抽屉卡片（N1）。**

### 2.4 v7 迁移与触发器（`trig.mjs`、`perf2.mjs`）

## 三、新问题与未解决问题

### P1

**P1-A　读缓存状态仍会因无关写入整套重算（P1-4 的遗留，未达验收口径）**
- 位置：`src/main/db.ts:280-284`（触发器无 `WHEN` 条件）、`src/main/stats/analysis.ts:128-152`（`checked_rev !== rev` 就调 `prepare()`）、`src/renderer/App.tsx:36-38`、`AnalysisPanel.tsx:16`。
- 问题：一份缓存分析的「是否过期」只取决于**计入统计的那批卷子**及知识点树 / 题型表；但修订号对任何卷子、任何阶段的写入都 +1。导入 20 份卷子时，提取、解析每个阶段都改 `papers`，`data:changed('papers')` 每 500 ms 合并一次，渲染端失效 `['stats']`，打开着同比页就会每次触发一次完整的 P2 输入构造。作者自测首次读 327.9 ms，我在 Node 里测 192 ms，期间主进程同步线程（`node:sqlite`）被占住，IPC 和流式 `ai:chunk` 都会卡。
- 修法（改动小）：让触发器只在「会影响统计」时才推高修订号：
  - `papers` 更新：`WHEN OLD.status IN ('done','reviewing') OR NEW.status IN ('done','reviewing')`，并只关注 `status / grade / semester / school_year_start / exam_type / textbook / region / file_hash / created_at / title` 这些列（`UPDATE OF …`）；
  - `questions` / `question_kps`：`WHEN EXISTS (SELECT 1 FROM papers WHERE id = <所属卷> AND status IN ('done','reviewing'))`（解析阶段写题时卷子是 `parsing`，不触发，转 `reviewing` 的那一次 `papers` 更新会 +1）；
  - `kps` / `qtypes` 保持现状。
  这样导入进度不再推高修订号；真正改了已计入卷子的数据才会重算。仍需把「重算」本身压到 300 ms 以内的话，再考虑 worker（作者已写进 M5）。
- 补测：写一个单测，对三类写入（out-of-scope 卷子的状态更新、in-scope 卷子的题改动、知识点树改动）断言修订号变化；把「核对结论是否复用」从 `analysis.ts` 里拆出不依赖 electron 的纯函数，补单测。

**P1-B　知识点抽屉的「基线」题目卡片不按学期对齐（新口径漏了一个出口，N1）**
- 位置：`src/main/ipc/stats.ts:62-72`（`side.kind === 'before'` 只传 `{ lt: target }`，没有学期集合）、`src/renderer/pages/dashboard/KpDrawer.tsx:19`（`qSide` 不带 `scope.align`）。
- 问题：同比四栏与 P2 已按「目标学年出现过的学期」取基线，抽屉里切到「基线」却是**之前全部学年的全部学期**。复现（`drawer.mjs`）：目标 2025 上 5 份；基线 2024 上 5 份（其中 2 份含 G.N）+ 2024 下 3 份（都含 G.N）。同比显示 G.N「消失，基线 2/5」，抽屉基线侧列出 **5** 张卡片（应为 2）。老师会拿卡片去核对「消失」，看到的却是对不上的 5 份卷子，其中 3 份根本不在比较范围里。
- 修法：给 `stats:questions` 的 `side` 加 `align: boolean` 和（或）让主进程用 `compare` 同款逻辑算出基线范围——最稳的是把 `compare()` 里「目标学期集合 → 基线 `PaperScope`」抽成 `core.ts` 里的一个导出函数（`alignedBaseScope(db, f, target, base, align)`），`compare`、`prepare`、`sidesEmpty`、`stats:questions` 共用，之后不会再有漏的出口。补一个 E2E（对齐开 / 关各看一次抽屉基线卡片数）和单测。

### P2

**P2-N1　SSE 最后一行没有结尾换行时，正常完成被当成中断（P1-3 的修法引入的边角回归）**
- 位置：`src/main/ai/client.ts:178-197`（循环只处理以 `\n` 结尾的行，流结束时 `buf` 里的残留不处理）、`:205`。
- 问题：服务商最后一个事件（`data: [DONE]` 或带 `finish_reason` 的块）后面没有 `\n` 时，旧代码会把它当完整结果，新代码当成 `network` 中断重试 2 次后失败，还白烧 3 次 token。复现（`eof.mjs`）：「最后一行 finish_reason 无结尾换行」「最后一行 [DONE] 无结尾换行」都报错并请求 2 次（`maxRetries:1`）。SSE 规范里事件以空行结束，大多数服务商没问题，但网关 / 代理偶有例外。
- 修法：循环结束后把 `buf` 里残留的一行也按 `data:` 规则处理一遍再判断 `finish / sawDone`；补两个单测。

**P2-N2　`BASE_YEARS` / `base.years` 列出了实际没有贡献卷子的学年**
- 位置：`core.ts:514`（`baseYears` 取自对齐前的 `availableYears`）、`core.ts:562`、`p2.ts:116`。
- 问题：基线 2023 年只有下学期卷子、2024 年有上学期卷子，目标只有上学期 → 对齐后只剩 2024 的 4 份，但交给模型的 `BASE_YEARS` 是「2023-2024学年、2024-2025学年」（`years.mjs` 复现，`BASE_PAPERS=4`）。模型会以为基线跨两个学年。
- 修法：对齐生效时，`baseYears` 取 `sB` 范围内真正有卷子的学年（一条 `SELECT DISTINCT school_year_start` 即可）。

**P2-N3　对齐后基线为空时，提示把原因说成「没有试卷」**
- 位置：`CompareTab.tsx:85`（`compare-empty`）、`core.ts:614`（总览 `reason`）、`CompareTab.tsx` 里 `align-note` 只在非空分支。
- 问题：目标学年的卷子学期全是「未填」，或目标只有上学期而基线只有下学期，默认（对齐）就得到空结果，页面只说「基线……没有计入统计的试卷」，总览写「没有更早学年的试卷可比」，而 `cmp.align.dropped` 其实有数（我复现的两个例子都是 dropped=5）。老师不知道该去关「按学期对齐」。
- 修法：空结果且 `align.on && align.dropped > 0` 时说明「有 N 份基线卷子因学期与目标学年不一致被排除，可以关掉『按学期对齐』」；总览 `reason` 同理。

**P2-N4　同比页的范围说明（待审核 / 重复）按筛选栏范围统计，不是同比实际范围**
- 位置：`Parts.tsx:26`（`stats.notes(filter)` 用完整筛选，含学年）、`CompareTab.tsx:82`。
- 问题：筛选栏选了学年时，同比页显示的重复 / 待审核份数只算那一个学年；没选学年时又算上同比没用到的学年和被对齐丢掉的学期。字面上满足了「四个页面都提示」，但数字与该页的卷数对不上。
- 修法：同比页给 `NotCounted` 传「目标 ∪ 基线（含对齐）」的范围，或在文案里改成「筛选范围内共有 N 份……」并说明与同比范围可能不同。

**P2-N5　打开「含待审核」会让已确认的副本被未确认的原件顶掉**
- 位置：`filter.ts:87`（`ORDER BY o.created_at, o.rowid`，不看状态）。
- 问题：原件 reviewing、副本 done 时，默认统计副本（已确认）；打开「含待审核」后代表变成原件，副本的已确认内容不再计入，数字内容变了但「份数不变」，横幅只说「N 份待审核已计入」。这符合协调方定的口径（「取可见、最早导入的」），所以我没算错误，但行为反直觉。
- 建议：协调方确认是否改成「先 done、再 reviewing，同状态按最早」；改的话只需把排序加一列 `CASE WHEN o.status='done' THEN 0 ELSE 1 END`，并更新单测与口径说明。

**P2-N6　测试缺口：去重 × 学期对齐叠加、抽屉对齐**
- `stats-core.test.mjs` 没有「同一文件两份 + 学期对齐」的组合用例（我手算的 D4 通过了）；E2E 没有对齐开 / 关下的抽屉用例。建议把 `fuzz.mjs`（独立朴素实现对拍）收进单测，成本低、覆盖面大。

**P2-N7　`docs/设计方案.md` 没有随返工更新**
- §3 `ai_analyses` 仍写「`cache_key` = hash(scope, `prompt_version`, `fingerprint`)、过期原因 data / prompt version」，实际已是「范围 + system 文本 + user 文本」的哈希；v7 的 `data_rev`、触发器、`checked_*` 列没有记录；§4 没写「同一文件只算一份」与「同比默认按学期对齐」（口径文档）。
- 修法：补这三处（交付说明 §10 说改过设计方案，但只是返工前的版本）。

**P2-N8　BOM 仍是源码里的不可见字符，说明写成已改**
- 位置：`csv.ts:4`；交付说明 §3.4、§12-P2-6。编辑器 / 格式化工具可能吃掉它，导出的 CSV 就会在 Excel 里乱码。改成 `'﻿'` 即可，同时更正说明。

**P2-N9　跨侧重复文件的边角**
- `availableYears`（`core.ts:495`）用 `'ignore'` 范围，在**所有学年**里去重；`compare` 两侧各自去重；P2 的跨年高频表 `both` 又是并集去重。同一个文件的两份分别落在目标学年和基线学年时（比如有人改了其中一份的学年），`hot` 的分母（`h.papers/hotRes.papers`）会比 `nT + nB` 少 1，学年下拉里也可能少一个学年。极少见，改前请先决定「跨学年的同一文件算不算重复」。

**P2-N10　对齐时 `SAMPLE_WARNING` 不写学期范围**
- 协调方要求「P2 的样本说明要写清学期范围」。目前学期范围写在 `FILTER_DESC`（总是有），`SAMPLE_WARNING` 只在不对齐时带「学期构成不一致」（经 `mixed`）。对齐且样本偏小时，`SAMPLE_WARNING` 只有「样本偏小……」。我认为通过 `FILTER_DESC` 已基本满足；若要严格按字面，在 `sampleWarning` 里补一句即可。

## 四、对重点问题的直接回答

1. **P0-1 / P1-1/2/3/5/6 的测试在修前会失败吗？** 是（见第一节，我在副本里逐个改回去验证）。P1-4 的「复用核对结论」和 P1-6 只有 E2E / 性能脚本，没有单测。
2. **去重与对齐叠加数字对吗？** 对（D4 + 2100 组对拍）。
3. **触发器是否覆盖所有影响统计的写入？** 覆盖，没有漏路径；问题是太宽（P1-A）。
4. **触发器是否拖慢写入？** 不显著（导入 +12%，审核单行更新无感）。
5. **四个页面卷数是否对得上？** 对得上；抽屉卡片对不上（P1-B）。
6. **交付说明 ✅ 与实际是否一致？** 绝大多数一致，已知缺口也写得基本诚实；不一致的有：§3.4 / §12-P2-6「BOM 已写成 `﻿`」不实；§3.7「读状态不再整套重算 ✅」应写成「修订号没变时不重算，数据一变首次读仍要重算」（§5 / §8 里已有，但 §3.7 与 §12 的 P1-4 行措辞偏满）；§8「已知缺口」没提到抽屉不按学期对齐、SSE 末行无换行、`BASE_YEARS`、对齐后为空的提示、同比页范围说明的数字范围、设计方案未更新。

## 六、结论
