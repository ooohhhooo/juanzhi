| 功能 | 状态 | 验证方式 / 说明 |
|---|---|---|
| 状态流 `extracted → parsing → reviewing → done \| failed` | ✅ | E2E 全流程；失败有 `error_stage`（extract / parse），解析失败保留页面数据，可不重新提取直接重试 |
| 文本版输入：`[页-行]文字`，行按 (y,x) 重排并合并同一水平线上的碎片，康熙部首（⼆⼀⾳）归一为普通汉字 | ✅ | 单测用 g4-2025-page1.png 的真实 OCR 乱序行（`_. It's cold` 排在第 13 题之后）验证并回第 10 题那一行；E2E 检查发给模型的 user 文本（`第二学期`、`[1-04]1. A. farm…`、无部首字符）。**这同时收掉了 M1 备忘的「行按 (y,x) 排序」「anchor 空白归一化」** |
| 按页/字数分批、对半拆小、跨批合并、`PREV_CONTEXT` | ✅ | 默认每批 ≤3 页、≤3000 字；单测覆盖切批规则与续写合并（整条替换、材料追加、大题实例号）；E2E：每批 1 页时第 1 批末尾的未完成题带入第 2 批的 `PREV_CONTEXT`，续写合并成 36 题（不是 37），材料 id 前缀 `b1-/b2-`；输出被截断时对半拆成每页一批 |

### 3.3 故障场景（每个都有中文原因、可重试）

全部在 E2E 里对着 mock 的故障脚本验证，状态 failed 的都核对了 `error_stage='parse'`、文案是中文且不含英文堆栈。

| 场景 | 行为 |
|---|---|
| 空 content | 先同参数重试一次，仍空则对半拆小；两页都不行 → failed「模型返回了空内容（重试后仍为空）」。只空 2 次时拆批后成功（4 次请求：2 空 + 每页一批） |
| 非法 JSON | 带反馈让模型重来一次；持续非法 → failed「输出不是合法的 JSON…」 |
| 结构不符（难度 9） | 同上，错误里指出 `questions[0].difficulty：不能大于 5` |
| 429 | 按 Retry-After 退避自动重试；持续 429 → 共 4 次请求后 failed「请求太频繁或额度不足（HTTP 429）」 |
| 5xx | 指数退避重试 |
| 超时 | 一次超时自动重试；持续无响应 → 4 次后 failed「模型响应超时」（E2E 把超时设为 2 秒） |
| 批次被截断（finish_reason=length） | 不硬解析残缺 JSON，对半拆批重试；单页也被截断 → failed「输出被长度上限截断」并指明页码 |
| 401 | 不重试，failed「API Key 无效或没有权限」 |
| 参数不兼容（response_format） | 自动去掉后重试 |
| 缺视觉模型 | 见 3.2 |

重试入口：队列页「重试 AI 解析」（界面点击已测）、下拉菜单里「仅重新定位 / 从头重试」。

### 3.4 处理队列

| 功能 | 状态 | 验证方式 / 说明 |
|---|---|---|
| 逐份试卷的阶段（提取文字 → 拆题与标注 → 定位题目 → 保存入库）、进度条、状态文案、错误原因 | ✅ | E2E 截图 m2-02/03/05；运行中实时显示「AI 解析中 8%」；失败显示「AI 解析失败：…」，展开行有详情 |
| 同时解析 2 份（可配 1–4） | ✅ | E2E：3 份同时入队、每次请求拖 6 秒，mock 观察到最大并发 = 2，队列里同时运行的任务最多 2 份，第 3 份「排队解析」 |
| 暂停 / 继续 | ✅ | E2E：暂停后拖入 3 份，都停在「排队中」、没有开始提取、没有请求 AI，页面有「队列已暂停」横幅；继续后自动走完。提取队列和解析队列同时受控。语义：正在跑的试卷做完当前这一步，不再开始新的 |
| 取消 | ✅（运行中）/ ⚠️（排队中的界面按钮） | E2E：解析中取消 → 回到开始前状态（旧题目保留），`parse_runs` 记 cancelled，不算失败。排队中取消只有代码 |
| 从指定阶段重试 | ✅（API）/ ⚠️（下拉菜单里的点击） | E2E：「仅重新定位」不再请求模型且题目重新生成；「重新 AI 解析」请求 1 次；「从头重试」清掉旧页面与旧题目、重新提取、即使关了自动解析也接着解析。菜单项本身的点击没测，测的是同一个 IPC |
| 强杀恢复 | ✅ | E2E：解析中 `kill -9` → 重启后有旧题目的回到「待审核」（旧题目完好）、从没解析过的回到「已提取」，`parse_runs` 标 interrupted，可再解析（M1 备忘「parsing 被中断时回到 extracted」） |
| 提取后自动解析 | ✅ | 默认开（已配置 AI 时）；E2E：关闭后停在「已提取」且不请求 AI；开着时 3 份自动走完 |
| 导航徽标 | ✅（仅队列徽标）/ ⚠️（审核徽标） | 侧栏「处理队列」「审核」带进行中/待审核数量；E2E 只断言了「处理队列」徽标（解析进行中时数字为 1–3），**审核徽标没有断言** |

## 4. 设计决定与偏离（请协调会话过目）

1. **采纳 `kp_suggestion` = 新建节点**，见 3.5。
2. **置信度由程序折算**（标记扣分 + 定位失败/无题干扣分，<0.7 标黄），不使用模型自评，依据提示词审阅意见 9。
3. **已存密钥不改发**（3.1）：任务书没要求，我认为值得；代价是换服务商时得重输密钥（本来就要换）。
4. **提取队列也受暂停控制**，且新增 `extracted` 之后的自动解析默认开启（需先配置 AI）。
5. **`questions` 题号**：保留旧 `no`，权威列 `no_label`（见 3.6）。
6. **`'none'` 页（OCR 正常跑完但没字）**：按任务书发给视觉模型；没配视觉模型时跳过并在 AI 备注里说明（避免空白背面让整份失败）。`ocr_failed` / `needs_ocr` 页没有视觉模型则整份 failed 并提示。
7. **视觉版 bbox 的延伸启发式**：模型只框「题号 + 题干首行」，程序向下延伸到同页下一题的顶部（最后一题给 `max(3×首行高, 0.1)`），同一行的下一题限制右边界。
8. **材料单独存表**（`materials`），题目用 `material_id` 引用；审核页折叠显示。
9. **批次默认值**：≤3 页、≤3000 字、输出上限 8192 tokens，都可在「高级」里改；失败时按提示词 §7.1 对半拆小。
10. **自定义提示词版本号**：`v1.1+自定义·<哈希前 6 位>`（内置版本现为 v1.1），同一份改写得到同一个标识。
11. 审核页打开时**自动收起主侧栏**，并提供 150%/200% 缩放，因为 1200px 宽窗口下三栏会把原卷挤得很小。

## 5. 提示词里发现的问题（未改 docs/prompts，仅记录）

1. （**已按协调会话授权修掉**，见 §10 P2-24；以下是当时的发现）文本版示例用题型代码 `CHOICE`，而设计方案与内置题型表里的单项选择是 `MC`；示例里的知识点代码 `GR.NOUN.PLURAL_IRR`、`PH.VOWEL.AR` 也不在树里（真实代码是 `GR.NOUN.PLURAL.IRR`、`PH.PHONICS.COMBO`）。提示词声明了「示例代码仅为示意」，但模型仍可能照抄；程序有兜底（不存在的代码退回祖先/`OTHER`），建议把示例改成真实代码。
2. 视觉版 flags 枚举没有 `underline_lost`，改用 `<u>` 标签表达画线——程序把 `<u>` 原样存入，界面暂未渲染（见 3.2）。
3. 提示词说 `anchor_ref` 是「OCR 行标签」；程序给模型的行号是**重排并合并碎片后**的行（见 3.2），不是 `lines_json` 的原始行序。提示词不用改，但交付/评审时别拿 `lines_json` 的下标去对。
4. `meta.exam_type` 的取值写「单元」，应用枚举是「单元测试」，程序做了映射；`KNOWN_META` 的字段名（年级/学期/学年/考试类型/教材/满分）是程序自己定的，提示词里只有示例。
5. 「题目由 (section, no) 唯一确定」在「听力部分一、笔试部分一」这类大题序号重复的卷子上不成立。程序用「大题实例号」处理跨批出现的重复序号；**同一批内**出现两个同序号的大题，仍无法区分（后者的题目会被当作重复，丢弃并写入 AI 备注）。
6. 提示词 §七.3 的「`continued_from_prev=true` 整条替换」在程序里还额外强制沿用上一批的 `page/anchor/anchor_ref`（提示词要求模型这么做，但模型可能改动，程序兜底）。
7. 前缀缓存的前提是知识点树文本不变：老师「采纳」新建节点后，树文本变了，下一次解析会有一次缓存未命中——预期内。
