# 退费原因分析

退费表的核心是「原因」，通常是自由文字或不统一的选项。方法：**先归类，再计数，再拆人群，最后分清可改进与不可控**。

## 1. 先看数据概况，认列

先用 list_datasets 找到数据集，再用 dataset_profile 认出：

- **原因列**：文字（退费原因、备注、沟通记录）。有时有两列：一列选项（粗分类）、一列文字（详细说明）；两列都用，选项做粗分，文字做细分。
- **时间列**：申请退费日期、报名日期、上课开始日期、已上课次数——用来判断「退得早还是晚」。
- **金额列**：退费金额、已上课时、剩余课时。
- **维度列**：班级、老师、课程、校区、渠道、新老生、期次。
- **身份列**：学员编号（姓名、手机号若已代号化就用代号）。

## 2. 核对口径

- **重复记录**：同一个人同一笔订单多条（申请、审批、到账分别一条）要去重，说明按人还是按笔算。
- **缺失**：原因为空的有多少，单独算一类「未填写」，不要丢掉也不要硬猜。
- **范围**：数据覆盖哪段时间、是否包含部分退费 / 转班；转班不等于退费，要问清是否算。
- **分母**：想算「退费率」就需要同期的总学员数 / 报名数。如果数据里没有总人数，就**只说退费人数的构成，不说退费率**，并在「说不清的地方」里写明。

## 3. 文字原因归类

1. 用 text_classify 对原因列归类：不指定类别，让 AI 先看抽样后提出 5–10 类。
2. 把提出的类别（名称 + 定义）和每类条数告诉用户，问是否需要合并、拆分或改名；用户改完把 categories 传回，重跑一次。
3. 归类结果会写成表里的新列（多原因用「；」隔开）。一条退费可能同时属于多类，所以各类占比加起来会超过 100%——要提醒。
4. 「其他」超过三成说明类别没覆盖好，补类别重跑；归类由 AI 完成，抽查几条原话再引用。
5. 原话里的手机号、证件号等个人信息已自动去除；引用原话时再检查一遍，不要在回答里出现具体个人信息。

## 4. 计数与构成

- 用 run_query 按归类列统计人数（多类用 LIKE 或拆分），也可以用 stat_multi_choice（把归类列当多选题，分隔符「；」）得到各类占比与置信区间。
- 按人数从多到少排，写出前 3 类的占比和一句话解释。
- 如果有金额列，再按类别汇总退费金额——人数多的类别金额不一定最大。

## 5. 逐层拆分：哪类人群、哪个阶段退得多

- 用 stat_crosstab：行 = 原因类别，列 = 维度（班级 / 老师 / 新老生 / 渠道 / 课程等，有什么用什么）。数字用 count，看每行内各列占比。
- 「退费时机」：用 stat_distribution 看「已上课次数」或「报名到退费的天数」的分布（edges 分段，如 0–1、2–4、5–8、9+）。很早退（上 1–2 次就退）多半是预期不符或匹配问题，很晚退多半是效果或时间问题。
- 如果同时有各班的总人数，用 stat_ratio 算各班退费率，再用 stat_find_low_groups 思路找**退费明显偏多**的小组（direction 可用 high，对「退费」这个指标）。没有总人数就不能比率，只能比构成。
- 样本小（<30）的组只提示，不下结论。

## 6. 关联线索（相关，不是因果）

- 数据集里有满意度表时，关联后看退费人群的满意度是否更低、给出的意见和退费原因是否一致。
- 有到课表时，看退费前几周到课是否下滑。
- 写法固定为「退费人群中 X 的比例更高」，不写「因为 X 所以退」。

## 7. 区分「可改进」和「不可控」

给每个原因类别标一个建议属性，让用户确认：

- **可改进**：教学效果、师资匹配、课程安排、沟通服务、价格与价值感。
- **部分可控**：时间冲突（可否提供更多时段）、转学区。
- **不可控**：搬家、孩子身体、家庭变故、升学阶段变化。

把前三个可改进类别单独列出，各给一条可以马上试的动作建议（写成「建议」，不是结论）。

## 8. 结论与「这份数据说不清的地方」

- 退费原因是申请时填的，可能不是真实原因（客气话、随便填的）。
- 没填原因的、没有总人数的、关联不上的，如实说。
- 未退费但不满意的人不在这份数据里。

## 9. 口径说明

交付时附：去重规则、原因类别的名称与定义、「其他」和「未填写」的占比、归类由 AI 完成并可能有误判、样本小阈值（30）。

## 10. 产出

- **看板章节建议**（用 board_start、board_add_section、board_add_block 搭，board_preview 检查，board_export 导出）：退费概况 → 原因构成（条形图，标明可改进 / 不可控）→ 时机分布 → 人群 × 原因交叉 → 可改进建议。
- **名单**：按原因类别列出相关班级或老师的清单，便于复盘；个人名单只用代号。
